# perf: a preload scanner for setup scripts

A script's downloads start together, before its first line runs, without the
script changing:

```html
<script :setup>
  const Toc = await import("./Toc.html")         // today: download, wait...
  const Lesson = await import("./Lesson.html")   // ...then this one
  const Header = await C79.fetch("./header.html")
</script>
```

Status: proposal.

## Today

Each `await` of a component waits for its download before the next one is
asked for, so N imports in a row are N round trips. `$importAll` (RECORD
2026-11-05.import-all.md) fixes it for whoever rewrites the code; this is for
the code as written. The Vite plugin has no such chain - its `import()`s are
hoisted into the bundle - but a `C79.fetch` in a script, relative to the page,
is not hoisted, and runs one after another there too.

## The proposal

What a browser does for `<script src>`: look ahead, start the downloads, run
the code in its own order.

1. **Scan, once per script block.** A new `preloadSpecifiers(source)` in
   `transform.ts` walks the script's top-level statements (with
   `findStatementEnd`, which already knows strings, comments, regexes and
   brackets) and collects the literal specifiers of the ones that run
   unconditionally:
   - a declaration whose initializer starts with one, or an expression
     statement that does: `[await] import("x")`, `[await] $importAll([...])`,
     `[await] C79.fetch("x")`, `C79.fetchAll([...])`, `C79.importAll([...])`
     (and `Component79.*`);
   - a static `import ... from "x"` (a factory script's), which is top-level
     by syntax.
2. **Preload, the first time a definition renders**, before any of its
   scripts runs:
   - an `.html` goes to the component cache (`componentSource`), the entry the
     real request will find - under safe mode its precompiled script loads
     with it, as it always does;
   - anything else gets a `<link rel="modulepreload">`, which downloads and
     parses a module but doesn't evaluate it, so modules still evaluate in
     the order the script imports them. It carries the page's nonce, as the
     precompiled scripts do;
   - a specifier the modules map holds is skipped: it is already here.
3. **The script runs as it always has.** Each `await` finds its file in
   flight or done.

Each specifier resolves the way its call does: `import()` and `$importAll`
against the component's file, through the modules map; `C79.*` against the
page; a bare one through the import map.

## What it does not touch

- **Anything that might not run.** An import inside a function, a block, an
  `if`, a loop or a handler stays on demand - which is the point of
  "code splitting is the file system". A brace-less `if (x)` / `else` / loop
  header also guards the statement after it. A `try` block is skipped whole:
  unconditional in practice, but cheaper to miss than to reason about.
- **Computed specifiers**, data `fetch()`, and `$:` statements.
- **Order.** Components are parsed, and modules evaluated, when the script
  reaches them. The render stays progressive: a pane still appears when its
  own `await` finishes.

## What it costs

- One scan per script block (a `WeakSet` of the blocks already preloaded), so
  a thousand rows of one component scan once. Cache lookups after that are
  per definition, not per instance.
- A wrong guess is one extra download of a static file, never a change in
  behaviour: a misread statement, a script that throws before its import,
  a prop named `C79` the scanner can't see. A script's own top-level `C79`,
  `Component79` or `$importAll` declaration is seen, and turns those calls off.
- A failed preload is dropped (the cache already evicts failures); the real
  request tries again and reports its own error.

## Rejected

- **Rewriting consecutive awaits into a `Promise.all`.** It changes the code:
  modules evaluate out of order (a polyfill, a registration the next module
  needs), the render stops being progressive, and B is requested even when A
  fails.
- **Preloading with `cache(false)`.** There is nowhere to keep the download,
  so the real request would make it twice. Off means off.
- **Preloading a data `fetch()`.** It can have effects, depend on the one
  before, and a `Response` is read once.

## Open

- **Grandchildren.** When a preloaded `.html` arrives, its own scripts could
  be scanned too, so a child's imports start before the child renders.
- **Pages.** jq79 never sees a page's code; `C79.fetchAll`, or a
  `<link rel="preload" as="fetch" crossorigin>` in the HTML, is the page's
  way.
- **Measured how.** `benchmark:ab` measures CPU, and this saves round trips.
  The tests hold that the requests start together and the evaluation order
  holds; the gain is in a network panel, not in a benchmark.

## 2026-11-05: grandchildren

The first open item, done. A component the scanner preloads has its scripts
read as it arrives (`preloadFile`): their `<script>` bodies are cut out of the
text with a quote-aware regex - the component isn't parsed until it renders -
and scanned like any script, resolved against the child's own URL and with no
modules map, since a fetched component has none. So a chain of components
that each import the next is one round trip per level, not one per component
per level, and each level starts as soon as its parent's text is in, before
the parent renders.

Each file is read once (`preloadedFiles`, by cache key), which is also what
ends a cycle - two components importing each other. `clearCache()` and
`cache(false)` reset it along with the cache, since a file read for an empty
cache would otherwise never be read again.
