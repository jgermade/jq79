# An unrecognized `:` directive should say so

**Status:** proposal.

## The problem

On a real element, every `:`-prefixed attribute jq79 doesn't recognize falls
through the static-attr loop to `el.setAttribute` and lands in the document
verbatim:

```html
<button :disabled="busy">a</button>
<img :src="'/x.png'" />
<form :submit.prevent="go"></form>
```

renders as, with nothing on the console:

```html
<button :disabled="busy">a</button> <img :src="'/x.png'"> <form :submit.prevent="go"></form>
```

Three ways that bites, in rough order of how often:

- **Vue muscle memory.** jq79 has no per-attribute binding — `:attrs` is the
  whole story — so `:disabled`, `:src`, `:href` are the first thing a newcomer
  writes and the first thing that silently doesn't work. A broken image whose
  `src` never existed is a long way from the attribute that caused it.
- **A directive that exists, on the wrong syntax.** `:submit.prevent="onSubmit"`
  for `@submit.prevent` — the form keeps its native submit and navigates away.
- **A typo in a control attribute.** `:iff="ready"` renders the element
  unconditionally; `:eachh` renders it once. The failure looks like a data bug,
  not a spelling one.

In all three the expression's source text is now in the rendered HTML, which is
its own small leak: `:src="'/x.png'"` publishes a path the page never fetched.

Meanwhile `:model` — the one case where somebody deliberately went looking —
does warn, and isn't written to the DOM ([`src/jq79.ts`](../src/jq79.ts) in the
same loop):

```
jq79: :model on <p> does nothing - :model binds component tags only (for now)
```

That asymmetry is backwards. `:model` on a native element warns because
[`2026-07-15.model-directive.md`](2026-07-15.model-directive.md) parked the
feature and knew someone would try it; the far likelier mistakes say nothing.

## The proposal

Generalize the `:model` arm. An attribute starting with `:` that `isControlAttr`
doesn't claim, on an element that cannot still become a component, warns and is
**not** written to the element:

```
jq79: :disabled on <button> is not a directive - jq79 binds attributes through :attrs="{ disabled: … }"
```

**The guard is load-bearing, and it's the one `:model` already uses**:
`el instanceof HTMLUnknownElement || node.tag.includes("-")`. A tag whose
component hasn't resolved yet renders as an unknown element and keeps its
attributes; when the definition arrives the tag re-renders through
`renderNestedComponent`, where `:disabled` is a perfectly good prop. Verified:
`<Unknown :disabled="busy" />` stays `<unknown :disabled="busy">` today, and
must go on doing so without a warn.

Everything else that carries a `:` attribute reaches this loop by a different
road and is untouched: `<slot :item="x">` is handled by `renderSlot` before any
element is built, and `<template :slot.name>` is `isControlAttr`. Scoped slots
can't trip it.

## What it costs

- ~4 lines in the static-attr loop.
- **Nothing in-tree.** Patched the check in behind a probe warn and ran the
  suite: 649 passed, zero hits. No library test, fixture or tutorial exercise
  writes an unrecognized `:` attribute on a real element, so every warn this
  ships is a warn about someone's actual mistake.
- One line in [`docs/template-syntax.md`](../docs/template-syntax.md), under
  `:attrs` — the section a reader lands on after seeing the warn.

## Rejected

- **Actually supporting `:attr="expr"`.** The real fix for the modal case, and a
  much bigger one: `:attrs` was the deliberate answer to it, and a per-attribute
  form has its own design (precedence against `:attrs`, removal on falsy, the
  property-vs-attribute split that
  [`2026-07-15.property-directives.md`](2026-07-15.property-directives.md)
  already picks through). Naming it here so the warn doesn't read as a decision
  against it: if it ever ships, this arm becomes the binding instead of the
  warn, and nothing else moves.
- **Throwing.** A misspelled directive is a bug to live with while you find it,
  not a reason to refuse to render. jq79 warns for every other
  it-does-nothing case (`:model` on an element, `:html.allowed` without
  `:html`, `:deep()` in a scoped style).
- **Warning once per name per instance.** The `:model` typo warn is
  rate-limited because it fires per writeback; this one fires once per element
  per render, which is already once per mistake.
- **Dropping the attribute silently.** Fixes the DOM leak and leaves the
  debugging cost, which is the actual complaint.

## Open

- **Whether the message names `:attrs`.** It's the right answer for `:disabled`
  and the wrong one for `:iff`, and there's no way to tell them apart. Leaning
  toward naming it anyway — the Vue-shorthand case dominates, and a typo'd
  control attr is recognizable from the attribute name the warn prints. The
  alternative is a bare "is not a directive", which is honest and helps less.
- **Whether `:model` keeps its own message.** Slight preference for yes: it says
  "for now", which the parked plan still means, and the generic message would
  lose that.
- Nothing here touches the nested-component path, where an unrecognized `:foo`
  is a prop by design and must stay silent.

## 2026-08-07 — superseded, not implemented

Superseded the same day by
[`2026-08-07.attribute-directive.md`](2026-08-07.attribute-directive.md), which
binds `:foo="expr"` as a single attribute instead of warning about it. The user
proposed the binding on reading this plan's "Rejected" entry for it.

The two cannot coexist, and that is the whole of the argument. This plan buys
`:iff="ready"` being caught at the price of `:disabled="busy"` never working;
once an unrecognized `:` name is a legal attribute binding, there is nothing left
to warn about. The Vue trade, and the same one the `:class.<name>` shorthand
made when it turned a would-be-typo namespace into a feature.

What this plan got right and the successor keeps:

- **The guard.** `el instanceof HTMLUnknownElement || node.tag.includes("-")`
  turns out to be load-bearing for the binding too, and for the same reason: an
  unresolved component tag is not an element yet, and its `:foo` is a parameter
  the upgrade will re-read. Verified here before it had a second use.
- **The evidence that the diagnostic costs nothing in-tree.** 649 tests, zero
  hits from the probe. That measurement is why the successor could be confident
  no existing markup depends on `:foo` rendering as a literal attribute.

What it got wrong: the premise that the modal case is a *mistake* to be reported.
`:disabled`, `:src`, `:href` are not typos — they are people writing the feature
jq79 was missing. A diagnostic aimed at the most-wanted feature is a sign the
feature should exist.

The warn is not lost, only relocated. On a component tag the signature says with
certainty which parameters are undeclared, where an element could only ever
guess — see [`2026-08-07.signature-teeth.md`](2026-08-07.signature-teeth.md).

## 2026-08-25 — the premise is dead; two cases are not

Re-read as part of §7 of
[`2026-08-24.open-after-pr-12.md`](2026-08-24.open-after-pr-12.md), which calls
this file stale. It is, and the note above only says *why* it was superseded,
not what that leaves. Rendered against the library as it stands:

| written | renders | console |
|---|---|---|
| `<button :disabled="busy">` | `<button disabled="">` | — |
| `<img :src="url" />` | `<img src="/x.png">` | — |
| `<p :iff="ready">` | `<p iff="true">` | — |
| `<p :eachh="items">` | `<p eachh="1,2">` | — |
| `<form :submit.prevent="go">` | `<form submit.prevent="() => {}">` | — |

**The whole "Vue muscle memory" section is obsolete.** `:disabled`, `:src` and
`:href` are bindings now, exactly as
[`2026-08-07.attribute-directive.md`](2026-08-07.attribute-directive.md) said
they would be. Anyone reading the top of this file today is reading a bug report
about behaviour that no longer exists.

What survives is the *genuinely* unknown, and it is two different problems that
this file's single proposal cannot cover with one rule:

- **A typo in a control attribute.** `:iff="ready"` renders the element
  unconditionally and leaves `iff="true"` on it; `:eachh` renders it once. The
  failure still looks like a data bug. There is no structural signal here at
  all - `iff` is a legal attribute name and a legal binding - so catching it
  means a near-miss check against `CONTROL_ATTRS`, which is a different
  instrument from anything in this library and has its own false positives to
  argue about.
- **A directive in the wrong syntax.** `:submit.prevent="go"` keeps the form's
  native submit and navigates away, and writes an attribute literally named
  `submit.prevent` whose value is the handler stringified - the source-text leak
  the original section described, still live, and now the only case where it is.
  This one **does** have a structural signal, and the library already computes
  it: `plannableAttr` rejects a dotted `:` name wholesale except `:class.`,
  because `:model.`, `:props.`, `:slot.` and `:html.allowed` are the only other
  families that exist. A dotted `:` name belonging to no family is not a
  plausible attribute anybody meant to bind.

So the rewrite this file needs is: **drop the modal case entirely, keep the two
survivors, and treat them as separate work.** The dotted-name warn is small,
needs no heuristic and cannot fire on a legal binding; the typo table is a
judgement call nobody has made. Neither is implemented, and this section is not
implementing them - it is saying which of the three original arguments is still
standing, because the other one is now the opposite of true.

What the file still gets right, and what the successor kept, is unchanged: the
guard, and the measurement that no in-tree markup depends on a `:` attribute
rendering verbatim.

## 2026-08-27 — the surviving half shipped, and the other one was refused by name

Twenty days after the rewrite above named the two survivors, the author took
both decisions, and neither went the way this file's last section assumed.

**The near-miss table was refused outright** - *"lo trataría como warning de
directiva desconocida, no quiero mantener una tabla de similares"* - and the
refusal was right about the cost and wrong about what was available: there is no
"unknown directive" category left to warn about. Since
[`2026-08-07.attribute-directive.md`](2026-08-07.attribute-directive.md), an
unrecognized `:name` **is** the feature, so a warning on all of them fires on
`:src`, `:disabled` and `:aria-expanded`.

What shipped instead is the rule that needs no table at all: **a `:` name that
starts with a directive's own name and is not one**. `:iff`, `:eachh`,
`:classs`, `:texts`. It is derived from `CONTROL_ATTRS` plus the two families
that are not in it, so there is no second list to keep in step - which is
exactly what the refusal was protecting against - and the message names the
attribute it bound and the directive it resembles:

```
jq79: :iff is not a directive - it bound an attribute named "iff". A ":name"
jq79 does not recognize binds that attribute (which is what :src and :disabled
are). If you meant :if, that is the spelling
```

It runs from `validateChains`, once per definition, and is silent on a component
tag where every `:name` is a prop by design.

**The dotted-name case (`:submit.prevent`) is still not implemented.** It is the
one thing this file proposed that nobody has argued with and nobody has written.

**And the third survivor was deleted rather than warned about.** This file's
`:attrs` half - the modal case it dropped - stopped existing on the same day:
[`2026-08-27.retiring-attrs.md`](2026-08-27.retiring-attrs.md). A retired name
gets a message of its own, from the same parse-time path.
