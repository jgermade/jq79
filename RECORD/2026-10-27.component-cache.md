# A component cache

## Problem

`Component79.fetch(url)`, `fetchAll` and an `import("./row.html")` from a setup
script all went through `fetchComponent`, which called `fetch()` every time. A
page whose components import the same child - a list of cards each importing
`avatar.html` - asked the network for that file once per importer. The HTTP
cache usually answers, but not always (`no-cache` headers, dev servers that
revalidate, the dev server's own `no-store`), and every answer is still a round
trip through `fetch` and a `Response`.

## Proposal

A module-level `Map<absolute URL, Promise<string>>`, on by default:

- **The text, not the component.** `fetch()` has always handed back a fresh
  instance; a caller mounts it, destroys it, `.on()`s it. Sharing one instance
  across calls would make two `fetch(url).mount()` the same component. Parsing
  stays per call; the network goes.
- **A promise**, so concurrent requests share one download.
- **A failure is dropped**, so a 500 doesn't stick.
- **Keyed by absolute URL, hash dropped**, so `./a.html`, `/a.html` and
  `a.html#x` from the same page are one entry. Query strings stay: they may
  name a different file.
- **Safe mode**: the entry settles after `loadPrecompiled` too, so the
  precompiled script is also loaded once per file.
- **Hot reload**: `hotUpdate` overwrites the entries of the edited file with the
  new source; otherwise a component mounted after an edit would render the
  pre-edit file.

API: `Component79.cache(enabled?) → boolean` (off drops the entries) and
`Component79.clearCache()`.

## Cost

A few lines, and memory: the source text of each fetched file for the life of
the page. Components are small text; a page that fetches thousands of distinct
URLs can turn it off.

## Rejected

- **Caching parsed parts** (`ComponentParts`): saves the parse too, but parts
  carry sibling *definitions* (Component79 instances), which `const { Row } =
  await fetch(url)` hands to the caller, who may mount them. Sharing them across
  calls brings back the shared-instance problem one level down.
- **Off by default**: the user asked for it on; and the semantics a caller sees
  don't change - only the number of requests does.
- **A per-call option** (`fetch(url, { cache: false })`): no caller needs it yet.

## Open

- No size bound or expiry. A long-lived page whose components change on the
  server keeps the version it first saw until `clearCache()` or a reload.
