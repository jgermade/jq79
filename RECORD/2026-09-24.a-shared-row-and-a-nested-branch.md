# A row over a shared store, and a branch inside a branch

**Status:** implemented. Two bugs reported against 0.7.2, each with a minimal
reproduction, found in an app that worked around both.

---

## 1. Rows over a `$reactive` held by a component never update

```js
const store = $reactive({ list: [{ id: 0, busy: true }] })
// <li :each="item in app.list">{{ item.busy }}</li>, with app = store
store.list = [...store.list, { id: 1, busy: true }]
store.list.find(i => i.id === 1).busy = false   // the row still says true
```

Reported as "elements that arrived with a replacement"; reproduced, it is every
row - `store.list[0].busy = false` is as stale. The report's working originals
were most likely woken by something else on the page reading through `app`.

**Why.** Tracking spans stores (`trackerStack` is module-level), waking did not.
The row binding's effect lives in the component's store and read `item.busy`
straight off the shared store's proxy, so it recorded `list.1.busy` - the shared
store's path - in the component's index. The shared store's write notifies its
own effects (none of them) and `$onAny`, which the bridge re-notifies upstairs
as `app.list.1.busy`. That path matches nothing the row holds. Effects that read
`app.…` got through only because the bridge wakes every effect sitting on
`app`, whatever changed below it.

**Fix.** A store read by an effect it doesn't hold *adopts* it - registers it,
as slot content is registered with both its stores (`$__attach`). Per run: an
effect whose settled run no longer read a store is released by it, or
`current = second` leaves `first` waking it under the namespace-free paths it
reads off `second`. `$dispose` releases the holder's effects too. The bridge's
catch-all then skips effects the nested store holds (`$__holds`): they are
woken by exact path there, and waking them upstairs as well ran them twice.

**Costs.** One pointer comparison per tracked read (`effect.home !== effects`),
and a `Set.add` per read that does cross a store. The namespace-free paths
already accepted for slot content now apply to any cross-store read: a name in
both stores wakes the effect from either - a spurious run, never a stale one.

**Rejected.** Re-notifying the bridged change unprefixed in the holder as well
(`list.1.busy` next to `app.list.1.busy`). It works for single writes, but a
replacement reaches `$onAny` as the container alone, so the holder would sweep
every row under `list` - the whole-list wake `notifyReplaced` exists to avoid -
where adoption lets the nested store's own difference walk decide.

## 2. A nested `:if` evaluates against the value that closed its parent

```html
<div :if="toast"><button :if="toast.action">{{ toast.action.label }}</button></div>
```

`toast = null` logged `Cannot read properties of null (reading 'action')`.

**Why.** Not an ordering problem - the outer chain's effect is older and runs
first, and disposes its branch. But a chain's branch scope (`branchFx`) was
disposed only by *its own* chain's effect, never by the scope the chain was
rendered into; `:each` rows the same. So the inner chain's branch outlived the
outer branch: the interpolation was still registered, and ran. Beyond the error
it was a leak - every nested branch or list inside a removed branch kept its
bindings on the store for good, which with bug 1 fixed would mean on a shared
store that outlives the component.

**Fix.** `fx.onDispose` for the branch in `renderConditional` and for the rows
in `renderEach`, as component tags and slot content already did.
