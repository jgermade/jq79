# Cache what a script's text compiles to

## Problem

A downstream app (~130-row list, jq79 0.7.12) spends up to 720ms on a view
switch in Chromium, and the CPU profile puts ~1100 of 1700ms in reading
component scripts: `findExportDefault`, `transformSetupScript`,
`transformFactoryScript`, `splitTopLevel`, `parsePropsPattern`,
`patternCloseIndex`, `findStatementEnd`, `splitDeclarators`.

`renderWith` runs, per instance and per script:

- `transformFactoryScript(script.content)`
- `parseFactoryProps(script.content)` - in the script loop, and again in
  `declaredPropNames` (every render) and `declaredPropSet` (every prop pass)
- `transformSetupScript(script.content)`
- `setupSignature(script)` → `parsePropsPattern(script.attrs[":setup"])`

Every one of them is a pure function of a string that is the same for every
instance of a definition. The Vite plugin's precompile covers template
expressions and the `new Function` of the scripts, not these text passes.

A quick patch that memoized the four by text took the view switch from 720 to
329ms and 241 to 107ms in that app.

## Proposal

Memoize them in `jq79.ts`, keyed by the source text, the way `compiled`
already memoizes expressions:

- `factoryCodeOf(content)`, `factoryPropsOf(content)`, `setupTransformOf(content)`
- `setupSignature` reads the pattern through `signatureOf(pattern)`; its
  warning stays where it is (keyed by the block, once).
- `declaredPropNames` (source.ts) takes the factory-props reader as an optional
  third argument, defaulting to `parseFactoryProps`, so the runtime hands it the
  cached one and precompile keeps the plain one.

Cached values are shared by every instance, so they are frozen (the arrays) on
the way in: nothing reads them mutably today, and freezing makes sure nothing
starts to.

`parseFactoryProps` throws the pre-0.4 migration error. A throw is not cached -
it rethrows on every render, exactly as now; only the error path pays.

## Cost

One `Map` lookup per call. The maps hold one entry per distinct script text,
the same growth `compiled` already has per distinct expression; under HMR an
edited script adds an entry and the old one stays - a few strings per edit, in
dev only.

## Rejected

- **Caching inside `transform.ts`.** It would cover precompile and the editor
  too, but the language server is long-lived and re-reads a script on every
  keystroke: an unbounded map there grows per edit for hours. Those callers
  read each script once per build/check anyway.
- **Keying by the `TagBlock` (WeakMap).** Frees with the definition, but two
  `new Component79(src)` from the same string parse twice and share no blocks;
  keying by text covers both.
- **Caching per definition on the instance.** Same as above, and more state.

## Open

- Unbounded under very long HMR sessions; an LRU is the fix if it ever shows.
