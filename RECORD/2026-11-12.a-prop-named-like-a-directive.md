# A prop named like a directive

**Status:** proposed and implemented on the same branch. Issue
[jgermade/jq79#44](https://github.com/jgermade/jq79/issues/44).

## The problem

`:value`, `:checked`, `:selected`, `:text`, `:html` and `:class` are directives.
`renderNestedComponent` skips every control attribute when it collects props,
so on a component tag they never reach the child:

```html
<Toggle :checked="on" />          <!-- Toggle's `checked` prop is undefined -->
```

Nothing says so. jackbird's answer is a rule in its contributor notes (`chosen`
for `selected`, `model` for `value`), which is the library failing silently and
the app documenting around it.

## The proposal

Warn, once per usage site, when a component tag carries one of these and the
component's signature declares a prop of that very name - the case where the
author clearly meant a prop. Name the fix: rename the prop, or use `:model`
for a value that goes both ways. And list the reserved names in the props docs.

Not warned: a tag carrying `:class` for a component that declares no `class`
prop - that is not a prop mistake, and what `:class` on a component tag does is
its own question.

## Rejected

- **Pass them through as props.** It would change what `:value` on a component
  tag means for components that never declared one, and the same name would be
  a directive on an element and a prop on a tag - exactly the ambiguity the
  warning is about.

## Cost

One loop over the tag's attributes, once per usage site, at wiring time.
