# One precompiled script per build, preloaded

## Problem

Under `jq79({ safeEval: true })` a build emitted one classic script per
component (`Card.html.jq79-[hash].js`), and each component's module waited for
its own with a top-level `await`:

```js
await safeEval(Component79, import.meta.ROLLUP_FILE_URL_<ref>)
```

The bundler puts the component modules in the entry chunk, so in an app with 27
components the 27 awaits sit in one chunk, one after another: 27 network round
trips in a row before the runtime can render anything. And none of them could
start before `main.js` had loaded and begun to run. This was the open item
"The extra round trip" in [2026-09-23.no-unsafe-eval.md](2026-09-23.no-unsafe-eval.md).

The wait itself isn't needed at that point: `new Component79()` compiles
nothing; functions are only looked up in `makeFunction`, at render.

## Proposal

**1. One script for the whole build.** Every component module awaits the same
URL. The `safeEval` helper module already keeps its `<script>` promises by URL,
so the first `await` downloads the script and the other 26 resolve at once:
27 requests become 1.

- The order doesn't matter: each entry on `__jq79precompiled` is identified by
  `(params, body)`, and the runtime drains the queue on every lookup.
- The script is **one `push` with each function once**. A function written in
  several components (`{{ name }}`) is the same `(params, body)`, so a second
  entry would only replace the first with itself. Components are concatenated
  in sorted file order, so the same sources give the same bytes and the same hash.
- Dev doesn't change: one script per component, at
  `/@jq79/precompiled.js?id=…&v=…`, so an edit reloads only that component's
  functions.

**2. The page preloads it.** In a build, `transformIndexHtml` adds
`<link rel="preload" as="script" href="…/jq79-precompiled-[hash].js">` to every
page whose entry reaches a component without a dynamic import (the entry chunk or
one of its static imports holds a component module). The script downloads in
parallel with `main.js`, not after it. A page that only reaches components through
`import()` gets no link: the preload would sit unused, and the browser warns about
that.

- The `href` resolves to the same URL the module asks for: `base` + the file
  name, or a path relative to the page under a relative `base`. No `crossorigin`,
  because the `<script>` the helper adds has none, and the two requests have to
  match for the preload to be reused.
- **Nonce.** A preload is checked against `script-src` (its destination is
  `script`), and under `script-src 'nonce-…'` a `<link>` without the nonce is
  refused (a CSP violation, then a second download by the real `<script>`). With
  Vite's `html.cspNonce` the link gets the nonce by itself: Vite's own
  `injectNonceAttributeTagHook` stamps `<link rel="preload">` and runs after the
  plugin's hook. Checked in Chromium (below).

## How, given Rolldown

The obvious way, emit the asset with no source in `buildStart` and fill it in
`buildEnd` with `this.setAssetSource`, works on Rollup (Vite 5 to 7) but not
on Rolldown (Vite 8): Rolldown has no `setAssetSource`, and `emitFile` needs the
`source` up front. The module still has to name the script when it is loaded,
which is before the build knows every component. So:

- `load` records each component's checked functions, and its module passes a
  placeholder string, `"__JQ79_PRECOMPILED_URL__"`, for the URL.
- `buildEnd` emits the asset with its full source, from the components still in
  the module graph (`this.getModuleIds()`). It keeps what earlier builds recorded
  and prunes what has left the graph, so a watch rebuild that skips a module's
  `load` doesn't drop its functions.
- `renderChunk` replaces the placeholder with
  `new URL("<file relative to the chunk>", import.meta.url).href`. That is
  exactly what `import.meta.ROLLUP_FILE_URL_<ref>` rendered to before (checked
  on Vite 8, with `base` absolute, relative and a full URL). `renderChunk` runs
  before minification on both bundlers, and the chunk's hash includes the change.
  The replacement is on a line of its own, with only `)` after it, so the
  chunk's source map is returned unchanged (`map: null`).

The sketch also joined the per-component scripts with `"\n"`. Each one ends in
`)` and the next starts with `(`, so there is no automatic semicolon:
`push(…)\n(self.__jq79precompiled = …)` calls what `push` returned and throws a
TypeError. One `push` avoids that.

## Checked

`tests/vitePlugin.test.ts`:

- one asset, `jq79-precompiled.js`, emitted in `buildEnd` and not before, with
  every module awaiting the placeholder and `renderChunk` writing the URL;
- a lib build of `parent.html` + `user-card.html` rendering with `Function`
  blocked, from that one script, **loaded once** for two awaiting modules;
- a function written in two components is in the script once; loading the
  components in the other order gives the same bytes; a component that left the
  graph leaves the script; no component, no asset;
- a four-page app: the page that imports a component and the nested page that
  reaches one through a shared chunk both get the `<link>`, and its `href` is
  the file every module asks for; the page that only has `import()` and the
  page with no component get none; under `base: "./"` the `href` is `./…` and
  `../…`, and with `html.cspNonce` the link carries the nonce; with `safeEval`
  off, neither the asset nor the link.

With the dedupe or the page check removed, those cases fail.

`npm run check:csp`, in Chromium: on both Vite pages (`script-src 'self'`, and
`script-src 'nonce-…'` filled per response) the `<link>` is there, the script
is requested **once**, at the preload's URL, and there is no violation.

A one-off probe answered the nonce question. Same `{ nonce: true }` build,
three ways of serving it:

| `<link>`              | rendered | requests for the script | console                                           |
|-----------------------|----------|-------------------------|---------------------------------------------------|
| with the nonce        | yes      | 1                       | -                                                 |
| nonce stripped        | yes      | 2                       | `Loading the script '…' violates … script-src …` |
| no `<link>`           | yes      | 1                       | -                                                 |

So the link does need the nonce, and Vite's `html.cspNonce` gives it one.
Without it, the page still works, but the policy reports a violation and the
download happens twice.

The four-page app was also built by hand with Vite 5.4 and 7.3 (Rollup) and 8.1
(Rolldown), minified and with source maps on. All three gave the same asset with
the same hash, the link on the same two pages (nonce included), the same
`new URL("jq79-precompiled-….js", import.meta.url).href` in both chunks that
await it, and no warning.

## Cost

- A page can download functions for components it never uses. In jackbird, the
  app would also get the theme demo's. That is the price of one request.
- A function that doesn't compile is still warned about once per component, at
  `load`, with its file.

## Rejected

- **One script per output chunk** (built in `renderChunk` from the modules of
  each chunk): the precise answer to the cost above, but a chunk only knows its
  own modules, so an entry chunk and a lazy chunk would each need their own
  script and their own preload rules. Not worth it until an app shows the
  unused functions matter.
- **Dropping the top-level `await`** (the module would only register the pending
  load, and `mount()` would wait for it in safe mode): this makes `main.js` run
  without blocking, and in dev the per-component scripts would download in
  parallel too. But it touches the runtime and makes the first render in safe
  mode asynchronous. With 1 and 2, the one remaining wait overlaps with `main.js`
  and isn't worth that.
- **Guessing the reference id** so the module could carry
  `import.meta.ROLLUP_FILE_URL_<ref>` for an asset emitted later: Rollup derives
  it from a hash of the name, Rolldown from something else, and neither
  promises it.
- **Vite's `__VITE_ASSET__<ref>__` placeholder**: it would handle `base` and
  `renderBuiltUrl`, but it's Vite's internal format, and it still needs the
  reference id at `load`.

## Open

- **A nonce stamped by the server**, not by Vite's `html.cspNonce` (a proxy that
  adds `nonce=` to every `<script>`), has to stamp the `<link>` too, or the
  preload is refused as above.
- **`experimental.renderBuiltUrl`** isn't applied to the script's URL, neither in
  the module nor in the link. It wasn't before either: the module's URL is
  always relative to the chunk.
- **`'strict-dynamic'`** ignores `'self'`, so under `safeEval: true` with
  `strict-dynamic` and no nonce, the parser-inserted `<link>` is refused, and only
  the `<script>` the module inserts loads. Not measured.
