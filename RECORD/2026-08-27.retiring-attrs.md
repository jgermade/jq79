# Retiring `:attrs`

**Status:** the author's decision - *quitaría `:attrs` directamente* - taken on
the evidence below, and written before `src/` moves.

---

## Why it is on the table at all

[`2026-08-07.attribute-directive.md`](2026-08-07.attribute-directive.md) added
`:name="expr"`, the single-attribute binding, and it was argued *from* `:attrs`:
of the nine real uses in this repository, seven were one key. That argument
worked. What nobody did afterwards was ask what `:attrs` is still for.

Counted again today, every `:attrs` in the repository outside the docs:

| written | what it says now |
| --- | --- |
| `:attrs="{ disabled: index === 0 }"` ×2 | `:disabled="index === 0"` |
| `:attrs="{ readonly }"` | `:readonly` |
| `:attrs="{ disabled: saving, title: … }"` | `:disabled` + `:title` |
| `:attrs="{ style: \`width: …\` }"` | `:style="…"` |
| `:attrs="{ class: … }"` ×3 | `:class="…"` - and none of the three elements carries a static `class`, so the two are equivalent here |

**Nine uses, zero with a key set decided at runtime.** The repository does not
follow its own documentation, which already says *reach for it when the key set
is dynamic; for one known attribute, `:attr` says it in less*.

## What is lost, said plainly

`:attrs="bag"` - **attribute names not known when the template is written**, and
the removal of a name when it disappears from the object. Nothing else in jq79
can express that. A page that needs it drops to imperative DOM in its setup
script after `await $mounted()`.

That is the whole cost, and it is a real one. It is accepted because nothing
here needs it, because every framework that has the feature has it for
component-attribute *forwarding* (`v-bind="$attrs"`) rather than for elements,
and because jq79 forwards to a component through `:props` - which is not being
touched.

## What is gained

- **One directive fewer** in a language whose whole pitch is that it is small
  enough to read in a sitting.
- **The dead-attribute hole closes with it.** `:attrs="{ strokeWidth: w }"`
  writes an attribute SVG ignores, silently, and it is the *only* place that
  can happen: `:strokeWidth` is resolved against the parser's own table
  ([`2026-08-25.svg-attribute-names.md`](2026-08-25.svg-attribute-names.md)),
  and `:attrs` passes its keys through untouched. The open diagnostic item that
  has been on every list since - *`:attrs` writes a dead attribute without a
  word* - is answered by deleting the thing that does it.
- **One hole fewer in the cloner**: the `attrs` op is the one whose write is
  remove-then-add rather than a diff, and the only one left out of the
  comparisons added in
  [`2026-08-27.grouping-a-row-s-bindings.md`](2026-08-27.grouping-a-row-s-bindings.md).
- **The value rule stops being shared prose.** It belongs to `:attr` alone now.

## What it breaks, and what says so

`:attrs` becomes what any unrecognized `:name` is: **a binding for an attribute
literally called `attrs`**, which would write `attrs="[object Object]"` and
render nothing anybody wanted. On a component tag it becomes a prop named
`attrs`, where before it was skipped.

Silence there would be the worst version of this change, so a retired name warns
by name - the same parse-time path as the misspelt-directive warning added the
same day, and one entry rather than a rule:

```
jq79: :attrs was removed in 0.7 - it now binds an attribute called "attrs".
Bind them one at a time (:disabled="x", :title="y"), or :class for classes
```

## The migration, in this repository

Nine templates, one tutorial exercise (`01-basics/04-attributes`, whose README
teaches `:attrs` and whose solution uses it - both become `:disabled` +
`:title`, which is what the exercise was always about), the docs section, the
README mention, and ~20 assertions in `tests/renderComponent.test.ts` that pin
the value rule through `:attrs` and now pin it through `:attr`.

**The value rule itself does not change** - that is the point of it having been
shared - so those tests move spelling, not meaning.

## How each claim will be checked

| claim | sabotage that must turn it red |
| --- | --- |
| `:attrs` no longer binds several attributes | leave it in CONTROL_ATTRS |
| a retired `:attrs` warns, naming the replacement | silence the warning |
| `:attrs` now binds one attribute called `attrs` | assert the DOM without it |
| the value rule survives on `:attr` | drop the boolean arm and watch the corpus |
| the cloner has no `attrs` op left | keep the op and assert both paths agree |

## What is still open

- **A release note.** This is the third `feat!` since 0.6.4 and the version is
  still the author's to cut.
- **Whether `:props` should grow the dynamic-key job** for elements too. Not
  proposed here; the two are different mechanisms and merging them is its own
  argument.

## Update, 2026-08-27: what the migration found

Done, and two losses beyond the one this file predicted. Both come from the same
fact and neither was in the plan:

**The `class` and `value` ATTRIBUTES are now unwritable.** `:class` and `:value`
are reserved for their directives - the class list and the DOM property - so
`:attrs` was the only way to write either attribute:

```html
<div :attrs="{ class: base }" />       <!-- replaced the class attribute wholesale -->
<input :attrs="{ value: name }" />     <!-- wrote the value ATTRIBUTE, the control's default -->
```

Two tests pinned exactly those, as sharp edges rather than as features: one
documented that `:attrs`'s `class` key and `:class` wipe each other, the other
that a bound `value` attribute stops driving an input the moment somebody types.
**Both failure modes are gone with the directive**, so the tests are replaced by
comments saying where they went, and `:class` is now the only writer of the
class attribute in the whole language. `:checked` and `:selected` lose their
attribute forms the same way, and nobody has ever wanted those.

That is the honest shape of the loss: not "you cannot spread an object" alone,
but "four attribute names are only reachable through their directives now".

**And one thing that was already true came out plainly**: the value rule was
written to be shared between `:attr` and `:attrs`, and because it was shared,
retiring one of them moved twenty assertions' spelling and not one of their
meanings. A rule written twice would have made this a rewrite.

The migration in full: 9 templates, the `01-basics/04-attributes` exercise
(README and solution), the docs section, the README line, and assertions in
`renderComponent`, `parseComponent` and `skeleton` - including the corpus entry
`:attrs dropping a key it set`, which was a hole in the cloner that went with
the directive it was covering. 973 tests, three sabotages red.
