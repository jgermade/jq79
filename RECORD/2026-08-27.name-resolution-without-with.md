# Resolving a template expression's names without `with`

**Status:** a plan, measured on the box this session runs on (4 cores, node
22.22, the built bundle). It reopens the decision
[`2026-08-23.with-in-expressions.md`](2026-08-23.with-in-expressions.md) made -
*measure it, then don't do it* - because two of the three reasons it gave for
waiting have since stopped being true, and because the shape proposed here is
not the shape that was measured then.

It is the first half of an answer to the item every open list has carried since
[`2026-08-23.create-gap-is-diffuse.md`](2026-08-23.create-gap-is-diffuse.md):
the remaining distance to Svelte is *one effect per binding*, and nobody has
been allowed to attack it because the two priced pieces were both refused.

---

## What the earlier file decided, and why

`with ($scope) { return (expr) }` is how every template expression has always
been evaluated. It is 60% of an evaluation over a store proxy, because `with`
resolves each free identifier through `[[HasProperty]]` - the proxy's `has`
trap as well as its `get` - and consults `Symbol.unscopables` besides.

It was refused for three reasons, all of them good at the time:

1. **A rewriter needs a JS parser.** The throwaway spike prefixed free
   identifiers with `$scope.` and could not tell a free name from a bound one
   (`items.map(x => x.id)`).
2. **The error channel dies with it.** `with` throws `ReferenceError` for a
   name that resolves nowhere, and `reportExprError` turns that into the
   message naming a dropped prop or a `function` declaration
   `transformSetupScript` left lexical. `$scope.foo` returns `undefined`
   silently. Six tests said so.
3. **3-10% is a lot of surface for a little money.**

## What has changed

**(1) is already in the repository.** `src/transform.ts` carries a real JS
scanner - `skipString`, `skipLineComment`, `skipBlockComment`, `skipRegex` with
its `regexAllowed` lookbehind, `lastMeaningfulBefore`, `findStatementEnd`,
`splitDeclarators`, `patternBindings`. It was written for setup scripts, which
are harder than expressions. A free-identifier walk is a consumer of it, not a
new instrument.

**(2) is a property of the rewrite, not of dropping `with`.** The spike lost
the diagnostic because it *rewrote the source*. The shape below does not touch
the expression's text at all: the names become `const` declarations in front of
it, and a name that resolves nowhere throws the same `ReferenceError`, with the
same wording, from a resolver we own. `MISSING_NAME_RE` reads it unchanged.

**(3) was measured on one expression with one name, and the price of `with`
scales with the number of names.** That is the finding this file exists for.

## The shape

For an expression whose free names can be extracted, compile

```js
new Function("$scope", "$r", `
  let $t;
  const row = ($t = $scope.row) !== undefined ? $t : $r($scope, "row");
  const selected = ($t = $scope.selected) !== undefined ? $t : $r($scope, "selected");
  return ({ danger: row.id === selected }
);`)
```

- **The expression's own text is untouched.** It sits inside the `return`
  exactly as authored, so nothing about operator precedence, template literals,
  regex literals or comments can be broken by a rewrite that does not happen.
- **The fast path is one proxy `get` per name** - the same `get` `with` would
  have done, so the dep tracking is identical - and no `has` trap at all.
- **`$r` is only reached when the read came back `undefined`**, which is where
  every semantic that `with` provided is restored:

```ts
const $r = (scope, name) => {
  if (name in scope) return undefined              // in scope, and genuinely undefined - or a tombstone
  if (name in globalThis) return globalThis[name]  // Math, JSON, console, Date
  throw new ReferenceError(`${name} is not defined`)
}
```

  The `has` trap is still consulted for the tombstone case that
  `2026-08-23.narrow-the-wake-rule.md` documented (`user ? user.name : "none"`
  after a `delete`), just not on every read of every name.

## What it is worth, measured on this box

200,000 evaluations against a `$reactive` store, through an `Object.create`
scope of the shape `renderEach` builds, median of 7 rounds:

| expression | `with` (today) | this shape | Δ |
| --- | --- | --- | --- |
| `row.label` - one name | 865 ns | **316 ns** | **−63%** |
| `{ danger: row.id === selected }` - two names | 1,515 ns | **429 ns** | **−72%** |
| `Math.max(row.id, selected)` - a global and two names | 1,778 ns | **895 ns** | **−50%** |

The global case pays `$r` on every evaluation (a miss, an `in scope`, an
`in globalThis`) and still halves. The decomposition behind it, same method:

| shape | ns/op |
| --- | --- |
| `with` + proxy - what jq79 does | 801 |
| `with` + plain object | 85 |
| `$scope.` + proxy | 322 |
| `$scope.` + plain object | 13 |

which reproduces the earlier file's table (695 / 76 / 279 / 11 on its box) and
says the same thing: **~60% of an evaluation is `with`, and none of it is the
tracking.**

**Two shapes were measured and lost.** They are worth keeping because each
loses for a different reason:

| candidate | 1 name | 2 names | why not |
| --- | --- | --- | --- |
| `"row" in $scope ? $scope.row : $g("row")` | 493 ns | 779 ns | the `has` trap costs ~190 ns per name, and it is only needed on the miss |
| the caller resolves, names become parameters | 302 ns | 425 ns | fastest, and it cannot see a global: `Math` would arrive as `undefined` |

The winner is within ~15 ns of the fastest thing measured and keeps every
semantic.

## How much of the repository it covers

Every distinct expression in `tutorial/`, `frameworks/keyed/jq79/`, `tests/`
and `docs/` - harvested by pattern, so a props *pattern* in a signature is
counted as an expression it never was:

| | |
| --- | --- |
| distinct expressions | 269 |
| free names extractable (no `with` needed) | **239 (89%)** |
| bail to `with` | 30 - **20 of them handlers** (`count = count + 1`, `query = $event.target.value`), 9 signature patterns the harvest miscounted, 1 interpolation |

Free names per resolvable expression: **169 have one**, 45 have two, 12 have
none at all, 10 have three, 3 have more.

A handler runs once, on a click. It is the one place where an evaluation's cost
does not matter, and it is where every assignment lives - so *the bail list and
the hot path do not overlap*, which is what makes the conservative extractor
affordable.

## The extractor, and what it refuses

`freeIdentifiers(expr)` returns `null` - meaning *keep `with`* - for anything
that binds a name, assigns to one, or resolves one dynamically:

`=>`, `function`, `class`, `let`/`const`/`var`, `eval`, `++`/`--`, and any
assignment operator. Everything else is a walk that skips strings, template
literals (recursing into `${}`), comments and regex literals, and collects
identifiers that are not a property name after `.`/`?.`, not an object-literal
key, and not a reserved word or literal (`true`, `null`, `this`, `typeof`, …).

**One more bail, for a semantic rather than a syntactic reason.** The `const`
prologue resolves every name *eagerly*; `with` resolves them as the expression
reaches them. For `cond ? a : b` that means eager tracking of a branch that was
not taken - correct, but a wider dep set than today, and a `ReferenceError` for
a name in a branch that would never have run. So: **an expression that
short-circuits (`?:`, `&&`, `||`, `??`) and has more than one free name keeps
`with`.**

Measured cost of that rule across the same 269: **one expression**
(`!proposal && !demo`, whose two names are booleans in the same store).

## What it costs

- **A second compile shape to keep in sync.** `compileExpr` caches one function
  per `(params, expr)`; it would cache one of two kinds. The call site changes
  from `fn(scope, ...extras)` to `fn(scope, $r, ...extras)` for the new kind.
- **The extractor is a correctness surface.** It is a scanner, not a parser: it
  can be wrong about what is a free name. The mitigation is structural rather
  than hopeful - **if the generated function fails to compile, fall back to the
  `with` form** instead of caching the failure, so a name the extractor
  mis-collects (a reserved word, `arguments`) degrades to today's behaviour
  rather than to `undefined`.
- **A wider dep set in the one short-circuit case**, if the bail rule above is
  ever relaxed.
- **Nothing about the store, the trie or `notify` moves.** This changes how a
  name is read, not what happens when it changes.

## What it does not do

It does not touch the **effect count**, which is the larger half of the same
~30ms: three bindings on a row are three effects, and an effect costs about as
much to exist as its deps cost to track. Reproduced here, 1,000 rows of three
bindings, `store.$effect` straight over a `$reactive`, no DOM:

| arrangement | create |
| --- | --- |
| 3 effects, one dep each - what `renderNode` does | 16.6 ms |
| 1 effect reading three deps - what Svelte compiles | **8.7 ms** |
| 1 effect, one dep - the floor | 3.9 ms |

That is phase 2, and it needs exactly the instrument this file builds: knowing
a binding's free names at parse time is what lets a row's bindings be grouped
into one effect without re-reading the DOM writes. It also needs a
compare-before-write on every binding (the text binding already has one) and a
decision about the creation-order guarantee. **Not in this change.**

Phase 3 is the consolation prize the earlier file named: the `isNewKey` full
sweep - the last O(all effects) path in the store - exists because "`with`
skipped the store entirely" for a name that did not exist yet. `$r` consults
the scope explicitly, so those reads become trackable and the sweep could
become precise.

## How each claim will be checked

Sabotage first, per the rule PR #13 earned:

| claim | sabotage that must turn it red |
| --- | --- |
| an expression with no `with` evaluates identically | make `$r` return `undefined` instead of throwing |
| a name that resolves nowhere still reports | drop the `throw` from `$r` |
| a tombstoned name takes the else branch | make `$r` skip its `in scope` check |
| a global still resolves | make `$r` skip its `globalThis` check |
| the extractor bails on an assignment | remove `=` from the bail list and watch a handler stop writing |
| a short-circuit with two names keeps `with` | remove the rule and assert the dep set |
| a mis-extraction degrades to `with`, not to `undefined` | make the extractor emit a reserved word |

## What I would do

Ship the resolution change alone, with the bail list wide and the fallback in
place, and measure it with `benchmark:ab` against `main` on one machine - the
operations dense in evaluations per millisecond (`selectRow`, `partialUpdate`,
`swapRows`) are where the isolated numbers predict it shows, and `create1k`
should move by a few percent at most. Phase 2 is where `create1k` actually
lives, and it is a separate decision with a separate file.

## Update, 2026-08-27: it shipped, and what the browser says about it

The change landed (`ad94631`, `f9335fc`), 932 tests became 963, and the
`scopedNames` flag exists so the two forms can be paired on one bundle -
`npm run benchmark:ab -- --flags scopedNames`, which is what the harness could
not do before (`c0a3bd1` generalises `--flags` past the cloner).

### Three refusals, not one - and two of them were found by reading

The plan named one bail rule (a short-circuit with more than one name). Reading
the diff for what no test would have caught turned up a second, and it is the
one that would have broken somebody's page:

**A called free name takes the with-object as its receiver.** `add()` inside
`with ($scope)` runs with `this === $scope`, so a factory component's
`{ items: [], add() { this.items.push(x) } }` reaches its own state through
`this` today. A `const` cannot reproduce that - the call gets `undefined`.
Measured: `with` returns the store, the prologue returns globalThis. 11 of this
repository's 239 resolvable expressions call a free name, 8 of them handlers, so
the rule costs 5% of the coverage and buys exact compatibility.

### Nine sabotages, and the two that could not go red

| sabotage | result |
| --- | --- |
| compileScoped never reached | **red** - both discriminator tests |
| `$r` returns undefined instead of throwing | **red** - the missing-name report |
| `$r` skips its `in scope` check | *green* |
| `$r` skips globalThis | *green* |
| the assignment bail removed | **red** - a handler stops writing |
| the short-circuit rule removed | **red** |
| the call-position bail removed | **red** - the receiver test |
| the demotion net removed | **red** - the `typeof` fallback |
| the prologue declares nothing | **red** - shadowing and the discriminator |

The two greens are the interesting ones, and the diagnosis was checked rather
than assumed: **the demotion net masks them.** Drop `$r`'s `in scope` branch and
a tombstone throws - which demotes the expression to `with`, which gives the
right answer. Remove the net *as well* and both go red immediately (two failures
and four). So each of those branches is observable only as cost - one permanent
demotion - and the net is what makes them so.

**What the sabotages found that the plan got wrong.** The plan claimed a name
the extractor misses "is slower, never wrong". It is not: the prologue does not
declare it, the expression reads it off globalThis, and where the page has a
global of that name (`name`, `status`, `length`, `top` - `window` has hundreds)
it silently reads the global instead of the store. Only a name that resolves
*nowhere* throws, and only that throw reaches the net. The claim is corrected in
the code comment; the differential corpus is what stands behind it.

**And the discriminator had to be found twice.** The obvious "did the new form
run" probe - a getter on the store, counting reads per mention - cannot work
through this API: `render()` spreads its data, so a getter is read once there
and never again, and the first version of that test asserted `reads === 1`
against a value that was `1` either way. The probe that works is
`Symbol.unscopables`: `with` consults it and refuses the name, the prologue
reads the property and does not.

### What the benchmark says

Chromium 141, Intel Xeon 2.80GHz × 4, one bundle against itself with the flag
off and on, alternating rounds. Two independent runs - 3 rounds × 8 samples,
then 4 × 10:

| operation | run 1 | run 2 | agree? |
| --- | --- | --- | --- |
| **Select a row** | **−15.5%, faster every round** | **−22.0%, faster every round** | **yes** |
| Create 10,000 rows | −4.2%, faster every round | −3.7%, faster every round | **yes** |
| Create 1,000 rows | −10.9%, mixed signs | −7.3%, faster every round | median, yes |
| Replace all 1,000 rows | −5.6% | −6.4% | median, yes |
| Clear 10,000 rows | −4.1% | −8.8% | median, yes |
| Update every 10th row | +2.1%, slower every round | +1.2%, mixed | slower in both medians |
| Swap rows | +0.7% | −4.9% | no |
| Remove a row | −0.8% | +4.2%, slower every round | no |
| Append 1,000 to 10,000 | +4.0%, slower every round | −3.3%, faster every round | **no - opposite** |

The runner's noise band is ±8% to ±39% depending on the operation, so no single
delta here is a result. What survives is the agreement:

- **`selectRow` is the win, and it is the one the isolated numbers predicted** -
  1,000 effects re-evaluated, one two-name expression each, almost no DOM.
  Faster in all seven rounds across both runs.
- **`create10k` and `create1k` move too**, consistently and by less, which is
  what a change to evaluation rather than to element construction should do.
- **`partialUpdate` is slower in both medians** by ~1-2% on a 2ms operation -
  at this runner's resolution that is one sample's jitter, and it is recorded
  rather than explained.
- **`appendToLarge` reversed sign between runs**, which is the reminder this
  file should end on: two runs of the same bundle disagreeing by 7 points is
  the box talking, not the code.

The number worth quoting is still the isolated one - 63% and 72% off a one- and
two-name evaluation, in a loop of 200,000 - because that one has a spread of a
few nanoseconds rather than a third of the measurement.

### Still open

- **Phase 2, the effect count**, untouched: 16.6ms of 1,000 three-binding rows
  against 8.7ms grouped, measured again here. That is where `create1k` actually
  lives, and it needs this extractor plus a compare-before-write on every
  binding.
- **Phase 3, the `isNewKey` sweep**, untouched.
- **A missed name that shadows a global** reads the global, as above. The
  differential corpus is the only thing standing under the extractor; a fuzz
  over every expression in the tutorial and the benchmark app would stand under
  it better.
- **`partialUpdate`'s 1-2%**, unexplained.
