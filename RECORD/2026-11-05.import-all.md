# feat: `Component79.importAll`, the plural of a page's `import()`

```js
const [Header, { formatDate }] = await C79.importAll(["./header.html", "./dates.js"])
```

does what

```js
const [Header, { formatDate }] = await Promise.all([import("./header.html"), import("./dates.js")])
```

does in a setup script - on a page, which has no setup script around it.

Status: proposal.

## Today

A page that loads a few components and a module writes the `Promise.all`
itself, and has to split it by kind: `fetchAll` for the `.html`, a native
`import()` for the rest, because a native `import()` of an `.html` is not a
component (browsers have no HTML modules). A setup script has no such split -
its `import()` is jq79's, and takes both.

## The proposal

A static `importAll(specifiers)` beside `fetchAll`, mapping each specifier
through the same `importResource` a setup script's `import()` reaches:

- `.html` -> the component, through `fetchComponent`, so the cache, the import
  map and safe mode's worker all apply as they do to `fetchAll`.
- anything else -> the module namespace, from a native `import()`.

Resolved in the same order and with the same rule as a script's `import()`
(`resolveSpecifier`), except the base: a page has no component file, so a
relative or root-absolute specifier means the page (`document.baseURI`) - the
same base `fetch` and `fetchAll` already use. A bare specifier is left for the
import map. Like `Promise.all`, the first failure rejects the whole call.

A plain promise, as `fetchAll` is, for the same reason: a list has no single
`mount`.

## What it costs

One static method and one type. The return type maps the tuple: a literal
ending in `.html` (or `.htm`) is a `Component79`, anything else `any` - which
is what a module namespace is without its types.

## Rejected

- **Resolving against the caller's module.** That is what a native `import()`
  means, and what `importAll` cannot know: the library's own `import()`
  resolves against `jq79.js`, and a stack trace is not an API. The page is the
  one base `fetch` and `import()` agree on - see `resolveSpecifier`'s comment
  for the CORS error the library's base produces.
- **Wrapping `.html` as `{ default: component }`.** A setup script's
  `import("./row.html")` gives the component itself; the plural shouldn't
  disagree with the singular it replaces.
- **Accepting a bare string.** `import()` is the singular; `fetch` refusing an
  array is the precedent for keeping the two apart.

## Open

- A bundler never sees these specifiers: under Vite, a page that wants its
  modules bundled imports them natively. `importAll` is for the no-build page.

## 2026-11-05: `C79` in setup scripts too

`Component79` was already injected into every setup and factory script;
`C79`, its short name, now is as well, so `C79.importAll([...])` reads the same
in a script as on a page. It is appended to `SETUP_HELPER_NAMES`, so the
positional parameters precompile reproduces gain one at the end and keep the
order of the others. A script's own `C79` (a declaration, a prop) shadows it,
as with every helper. It's a second name without a `$` from the library, which
the props rule (`$` comes from the library, the rest from the parent) already
carves out for `Component79`; the exception grows by an alias, not a new
meaning.

## 2026-11-05: `$importAll` for components

Using `C79.importAll` in the site's components showed what the first section
missed: in a script it is **not** the plural of `import()`. A script's
`import()` is the component's - relative to its file, and through its modules
map, which is how the Vite plugin bundles imports and how the tutorial's
preview answers `./Greeting.html` with the editor's next tab. A static method
knows none of that: it resolves against the page and skips the map, so an
exercise's `C79.importAll(["./CartLines.html"])` is a 404.

So components get their own: `$importAll(specifiers)`, an instance helper -
the `$` is what says it comes from the library and belongs to the component,
like `$emit` - that maps each specifier through the instance's `$import`.
Same answers as `Promise.all` of the script's `import()`s, including the
modules map. `C79.importAll` stays, for pages.

- **The Vite plugin** hoists the string literals of a `$importAll([...])`
  array as it hoists `import("...")`'s, so a bundled component's plural is
  bundled too. A non-literal entry is left to the runtime, as a computed
  `import()` is. `C79.importAll` is not hoisted: it means the page.
- **The editor** reads a `$importAll([...])` of literals as the
  `Promise.all([import(...), ...])` it is, so each component keeps its props
  type; anything else is `Promise<any[]>`.
- **The cost**: one closure per instance with a script, and one more
  positional parameter (appended to `INSTANCE_HELPER_NAMES`, so precompiled
  scripts from an older build stop matching, as with any helper change).

Rejected: a per-instance proxy of `C79` whose `importAll` is the
component's. The same spelling in both places, but `C79 !== Component79` in a
script, a proxy per instance, and a static method that means two things.
