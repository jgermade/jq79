# feat: `Component79.importAll`, the plural of a page's `import()`

```js
const [Header, { formatDate }] = await C79.importAll(["./header.html", "./dates.js"])
```

does what

```js
const [Header, { formatDate }] = await Promise.all([import("./header.html"), import("./dates.js")])
```

does in a setup script - on a page, which has no setup script around it.

Status: proposal.

## Today

A page that loads a few components and a module writes the `Promise.all`
itself, and has to split it by kind: `fetchAll` for the `.html`, a native
`import()` for the rest, because a native `import()` of an `.html` is not a
component (browsers have no HTML modules). A setup script has no such split -
its `import()` is jq79's, and takes both.

## The proposal

A static `importAll(specifiers)` beside `fetchAll`, mapping each specifier
through the same `importResource` a setup script's `import()` reaches:

- `.html` -> the component, through `fetchComponent`, so the cache, the import
  map and safe mode's worker all apply as they do to `fetchAll`.
- anything else -> the module namespace, from a native `import()`.

Resolved in the same order and with the same rule as a script's `import()`
(`resolveSpecifier`), except the base: a page has no component file, so a
relative or root-absolute specifier means the page (`document.baseURI`) - the
same base `fetch` and `fetchAll` already use. A bare specifier is left for the
import map. Like `Promise.all`, the first failure rejects the whole call.

A plain promise, as `fetchAll` is, for the same reason: a list has no single
`mount`.

## What it costs

One static method and one type. The return type maps the tuple: a literal
ending in `.html` (or `.htm`) is a `Component79`, anything else `any` - which
is what a module namespace is without its types.

## Rejected

- **Resolving against the caller's module.** That is what a native `import()`
  means, and what `importAll` cannot know: the library's own `import()`
  resolves against `jq79.js`, and a stack trace is not an API. The page is the
  one base `fetch` and `import()` agree on - see `resolveSpecifier`'s comment
  for the CORS error the library's base produces.
- **Wrapping `.html` as `{ default: component }`.** A setup script's
  `import("./row.html")` gives the component itself; the plural shouldn't
  disagree with the singular it replaces.
- **Accepting a bare string.** `import()` is the singular; `fetch` refusing an
  array is the precedent for keeping the two apart.

## Open

- A bundler never sees these specifiers: under Vite, a page that wants its
  modules bundled imports them natively. `importAll` is for the no-build page.
