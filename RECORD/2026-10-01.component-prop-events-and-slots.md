# A component prop's events and slots

**Status:** proposed.

## The problem

`Component<P>` ([2026-10-01.component-as-prop.md](2026-10-01.component-as-prop.md))
says what a component prop takes, and nothing about what it emits or which
slots it renders. In Toolbar:

```html
<Button @pressed="save">           <!-- completion offers no events -->
  <template :slot.icon>…</template> <!-- nor slots -->
</Button>
```

And a parent can pass a `Button` that never emits `pressed`, or renders no
`icon` slot: Toolbar's listener never fires, its icon is dropped, silently.

## The proposal

Two more type parameters, both optional:

```ts
import type { Component } from "jq79"

Button: Component<{ label: string }, "pressed", "icon">
```

- **In Toolbar**, `<Button @|` offers `@pressed`, `<template :|` inside it
  offers `:slot.icon`.
- **In a parent**, `:Button="Fancy"` is an error when Fancy doesn't emit
  `pressed` or doesn't render `<slot.icon>`. It may emit or render more.

`"~emits"` and `"~slots"` become functions of the name, `(event: E) => void`
and `(slot: S) => void`, for the same reason `"~props"` is one: Toolbar
*listens for* those names, so a component that emits more is fine, one that
emits fewer is not. The defaults, `never`, ask nothing: `Component<P>` means
what it meant.

What a component emits is read off its source (`$emit("x")`, `<slot.x>`).
A name that is computed (`$emit(name)`) can't be read, so such a component
is taken to emit anything: no false error.

## What it costs

- **Types only.** `Component` gains two defaulted parameters.
- **The checker's `"~emits"`/`"~slots"` change shape**, from a union to a
  function of it; completion reads the parameter.

## Rejected

- **A plain union (`"~emits"?: E`).** It checks the wrong way: a component
  that emits more than Toolbar listens for would be refused, one that emits
  nothing accepted.
- **Checking `@x` on any component tag against what it emits.** A wider
  change, for every tag, and listening for a name nobody emits isn't wrong
  at runtime (a wrapper may re-emit it). Out of scope here.

## Built

Same day, as proposed. Two details:

- **Slot names are camelCased** where they are read off a component
  (`<slot.header-bar>` is `headerBar`), as the runtime matches them, so
  `Component<{}, never, "headerBar">` takes either spelling.
- **A computed emit** is any `$emit(` whose first argument isn't a plain
  string literal (`$emit(name)`, `` $emit(`x-${y}`) ``): the component's
  emits are then `string`.
