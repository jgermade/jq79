# Scope `<style scoped>` on the source, not through the CSSOM

**Status:** proposed and implemented on the same branch. Issue
[jgermade/jq79#43](https://github.com/jgermade/jq79/issues/43).

## The problem

`scopeCss` parsed a scoped block into a `CSSStyleSheet`, rewrote each
`CSSStyleRule.selectorText`, and wrote the sheet back out from `rule.cssText`.
Only the selectors needed changing, but every declaration made the round trip
too, and the CSSOM does not promise to hand a declaration back as written.

Chromium (checked today, Playwright's build) serialises a shorthand that holds a
`var()` and is then partly overridden in the same block as empty longhands:

```css
/* in */
.tab { border: var(--w) solid var(--c); border-bottom-width: 0; }
/* out of rule.cssText */
.tab { border-top-color: ; border-top-style: ; border-top-width: ; … border-bottom-width: 0px; }
```

That is invalid, so the browser drops every one of those longhands and the
border is gone. Valid CSS, fine unscoped (and under `mountShadow`, which gets
`content` as written), silently broken scoped. jsdom does not reproduce it,
which is why nothing here caught it; jackbird found it in a desktop build and
now runs its own check against it.

It is the same lesson as the component-name rename
([2026-08-25.the-wrapper-and-the-css-rename.md](2026-08-25.the-wrapper-and-the-css-rename.md)):
what an engine serialises is its business, and a rewrite that depends on it
works in jsdom and not in a browser.

## The proposal

Scope on the source text: prefix the selectors, leave everything else as
written. A small scanner, the same shape as `renameComponentSelectors`:

- tracks strings, comments and `{}` nesting, and whether the current block holds
  rules (top level, `@media`, `@supports`, `@container`, `@layer`, `@scope`,
  `@document` - the list the rename already uses) or declarations (a style rule,
  `@font-face`, `@keyframes`' frames, …);
- in rule position, a prelude that is not an at-rule is a selector list: split
  on top-level commas (not inside `()`, `[]`, strings, or after a `\`), and each
  selector gets the attribute on its last compound, before its pseudo-element;
- a declaration block is copied verbatim, nested blocks inside it included
  (CSS nesting is relative to the scoped parent, which is what the CSSOM version
  did too: it only ever touched the top `CSSStyleRule`).

## What the round trip was doing for free

Two normalisations the old code leaned on without saying so:

1. **`:before` became `::before`.** The pseudo-element test was `indexOf("::")`,
   which only worked for the CSS2 single-colon spellings because Chromium had
   already rewritten them. On the source, `:before`, `:after`, `:first-line` and
   `:first-letter` are recognised by name.
2. **`from` became `0%` in `@keyframes`.** Harmless; a test asserted it. The
   test now asserts the frames are left alone, which is what it meant.

And two things it did that the text version does differently, on purpose:

- **Comments.** The CSSOM dropped them all. Now they survive in declarations and
  between rules; a comment *inside* a selector is removed (CSS treats it as
  nothing, so `.a/**/.b` is `.a.b`), since the attribute must not land inside one.
- **Unparseable rules.** The CSSOM dropped a rule whose selector it couldn't
  read (`:deep()`); now it is scoped and injected, and the browser drops it on
  injection. Same result, and the `:deep()` warning stays.

The comma split is also better than before: `scopeSelector` split
`selectorText` on every `,`, so `.a:is(.b, .c)` became two broken halves, the
setter rejected the result, and the rule stayed **unscoped**. Splitting at top
level only fixes that as a side effect.

## Cost

A few dozen lines, no dependency, no DOM - so the scoped rewrite no longer needs
`CSSStyleSheet` at all, and could move to `source.ts` beside the rest of the
text-side reading if precompile ever wants it. It runs once per definition. One
scan of a string should not be slower than a parse plus a serialise, but that is
an expectation, not a measurement.

## Rejected

- **Keep the CSSOM and warn in development when a declaration went missing**
  (the issue's fallback). It needs a second parse to compare against, still
  ships the broken CSS, and still depends on engine serialisation, which is the
  actual defect.
- **Re-serialise from `rule.style` by property.** Same dependency, more code.
- **Scope selectors in the CSSOM and splice them back into the source by rule
  offset.** The CSSOM has no source offsets.

## Open

- The scanner is a tokenizer of convenience, not a CSS parser. Things it does
  not model (an unquoted `url(` holding a `{` in rule position, a `@layer`
  statement with a block in an odd place) are left as written - which, unlike
  before, is still what the author wrote.
