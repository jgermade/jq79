# A dotted `:` name that belongs to no family is an `@` written wrong

**Status:** plan, written before `src/` is touched. It takes the first half of
§2 of [`2026-08-27.what-is-still-open.md`](2026-08-27.what-is-still-open.md) -
the last unimplemented piece of
[`2026-08-07.unknown-directive-warn.md`](2026-08-07.unknown-directive-warn.md).

---

## The problem

Measured on `main` at `201bd41`, jsdom:

```html
<form :submit.prevent="go"><button>ok</button></form>
```

```
HTML   <form submit.prevent="() => {}"><button>ok</button></form>
WARNS  []
```

The form keeps its native submit and navigates away on the first click, and the
page now carries an attribute called `submit.prevent` holding the *source text*
of a handler. Nothing is said.

It is `@submit.prevent` with the wrong sigil, which is the second of the three
mistakes [`2026-08-07`](2026-08-07.unknown-directive-warn.md) listed and the only
one still silent. The other two are covered: `:disabled` is the attribute-binding
feature (there is nothing to warn about), and `:iff` starts with a directive's
own name, so `warnDirectiveTypo` catches it.

## Why the existing warn cannot see it

`warnDirectiveTypo` looks for a name that **starts with a directive's name**:

```ts
const directive = DIRECTIVE_NAMES.find(known => name !== known && name.startsWith(known))
```

`submit.prevent` starts with none of `if`, `each`, `class`, `text`, `html`,
`value`, `checked`, `selected`, `key`, `with`, `elseif`, `else`, `props`,
`model`, `slot`. It cannot: the mistake is not a misspelling of a directive, it
is a **modifier list on the wrong sigil**. A different signal has to see it.

## The proposal

**A `:` attribute whose name contains a dot and belongs to no `.`-family warns.**
One `continue`-shaped arm in the loop `warnDirectiveTypo` already runs, before
the prefix search:

```
jq79: :submit.prevent is not a directive - it bound an attribute named
"submit.prevent". Dotted modifiers belong to an event: if you meant
@submit.prevent, that is the spelling
```

Behaviour is unchanged - it still binds the attribute, like every unrecognized
`:name` - and the check runs **once per definition** from `componentPartsFrom`,
never per render or per instance.

### The families it must not fire on

The rule is the residue of a list this file does not write down. Every dotted
`:` name that means something is already claimed by `isControlAttr` or by the
`:model` guard the same loop keeps:

| family | claimed by |
| --- | --- |
| `:class.<name>` | `isControlAttr` |
| `:props.<name>` | `isControlAttr` |
| `:slot.<name>` | `isControlAttr` |
| `:html.allowed` | `CONTROL_ATTRS`, in full |
| `:model.<name>` | the loop's existing `:model` guard |

So the new arm is placed after those `continue`s and needs no list of its own -
the same discipline as `DIRECTIVE_NAMES`, which is derived from `CONTROL_ATTRS`
rather than typed out. A directive family invented later is a `.`-family in
`isControlAttr`, and it is silent the moment it is added there.

### Why a dot, and not a list of event names

Firing only on `:<known-event>.<modifier>` would need a table of DOM event names
to keep in step with the platform, and would still miss `:mycustomevent.stop`.
The dot is a **structural** signal, which is the same reason `plannableAttr`
already rejects a dotted `:` name wholesale:

```ts
return !isControlAttr(name) && !name.includes(".")
```

That line is this rule, computed already, for a different purpose. An element
carrying `:submit.prevent` is *unplannable today* — the clone path refuses it —
and nobody ever asked why.

## What it costs

- Four lines in `warnDirectiveTypo`, no new module-level state.
- **Nothing at render time.** Parse-time, once per definition.
- **Nothing in-tree.** Grepped every `.html`, `.md` and `.ts` under `tutorial/`,
  `docs/` and `tests/`: 44 dotted `:` attributes, and every one of them is
  `:class.`, `:model.`, `:slot.` or `:html.allowed`. The only `:submit.prevent`
  in the repository is prose in `RECORD/`, describing this bug.
- One line in [`docs/template-syntax.md`](../docs/template-syntax.md), beside the
  bullet that already explains why a misspelt directive is not an error.

## What was rejected

- **Making it an error, or refusing to write the attribute.** `:model` on a
  native element does exactly that, and `2026-08-07` argued the asymmetry the
  other way round: an unrecognized `:name` *is* a feature, so a warn that also
  changed behaviour would make the feature conditional on a heuristic. Warn and
  bind, like `:iff`.
- **Rewriting it to `@submit.prevent`.** Guessing what the author meant, on a
  signal that is only probably an event. The message says the spelling; the
  author types it.
- **A second list of dotted families.** It would be the third place that has to
  learn about a new directive family, after `CONTROL_ATTRS` and `plannableAttr`.

## What is still open

- **A real HTML attribute with a dot in its name** is legal markup and would now
  warn. Nothing in this repo writes one, and no framework does; if one turns up,
  the escape hatch is a plain `.setAttribute` in a setup script. Filed, not
  designed around.
- **`@class.foo`** - the mirror mistake, an unknown *modifier* on a real event -
  still says nothing. `bindEvent` ignores modifiers it does not know. Out of
  scope here; it is a different signal (a known set of five, not a dot).

## How each claim is checked

Sabotage first, per the rule PR #13 earned - each must be red before the arm is
trusted:

| claim | sabotage that must turn it red |
| --- | --- |
| a dotted `:` name outside every family warns | delete the arm |
| the message names the attribute it bound and the `@` spelling | assert on the wrong half |
| `:class.`/`:model.`/`:slot.`/`:html.allowed` stay silent | move the arm above the family guards |
| a component tag is silent, where `:name` is a prop | drop the component guard at the top of the loop |
| the attribute is still bound, unchanged | assert `getAttribute("submit.prevent")` |
| it costs no render | it runs in the parse-time loop, which is the placement itself |

## Implemented, 2026-08-30

Shipped as planned: four lines in `warnDirectiveTypo`, placed after the family
guards, plus one bullet in `docs/template-syntax.md`. **985 tests** (from 982).

Five sabotages, each red before it was reverted, one per row of the table above:

| sabotage | result |
| --- | --- |
| the arm never runs | 1 failed |
| the message drops the `@` spelling | 1 failed |
| the arm moved above the family guards | **2 failed** - it fires on `:class.warn` and on `:model.uname` |
| the component guard removed | 1 failed |
| the dotted attribute warned about and then not written | 1 failed |

**Nothing in-tree fires it**, counted rather than argued: the arm was patched to
append every hit to a file and the whole suite run. Two hits, both from the two
tests written here. No fixture, no tutorial exercise and no docs example writes a
dotted `:` name outside a family.

One thing the test-writing found, and it is in the *test*, not the library: a
`<template :slot.row="row">` at top level is a component declaration without a
name, and warns as one. A scoped slot only means anything inside a component
tag, so the family test says `<Table><template :slot.row="row">…</template></Table>`.
