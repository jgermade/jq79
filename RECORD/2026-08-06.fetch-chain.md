# feat: chainable fetch, and fetchAll for the array form

`Component79.fetch(url)` returns a handle that can be mounted straight away, so
loading a component from a URL is one expression with no `await` and no wrapper
function. The array overload moves to its own name, `fetchAll`.

Status: proposal.

## Today

The smallest possible page — no build step, one component, mount it — cannot be
written as an expression:

```js
import { Component79 } from "https://jgermade.github.io/jq79/jq79.js"

const app = await Component79.fetch("./app.html")
app.mount(document.querySelector("main"))
```

`await` at the top level of a module is fine, so this *works*; it just reads as
two statements and a temporary for what is one idea. What we want is:

```js
C79.fetch("./app.html").mount(document.querySelector("main"))
```

`fetch` returns a `Promise`, which has no `mount`, so today that is a
`TypeError`.

## The proposal

### 1. `fetch(url)` returns a pending component, not a promise

A small handle class wrapping the in-flight fetch. Every method a caller would
reach for before the component exists — `mount`, `mountShadow`, `render`,
`renderShadow`, `on`, `off`, `detach`, `destroy` — queues onto the fetch and
returns the handle, so calls stay in order and the chain stays synchronous:

```js
C79.fetch("./app.html")
  .on("save", (event, payload) => persist(payload))
  .mount("main", { user })
```

The handle is **thenable**, resolving to the `Component79`. That is the
compatibility hinge: every existing call site is `await Component79.fetch(url)`,
including `importResource` — what `await import("./Row.html")` inside a setup
script resolves through — and all of them keep working untouched. It is also
what lets the handle sit inside a `Promise.all`, as the tutorial's loader does.

Queuing preserves the resolved value, so the two styles compose:

```js
const app = await C79.fetch("./app.html").mount("main")  // mounted component
```

### 2. `fetch([urls])` becomes `fetchAll([urls])`

Same `Promise.all` semantics as the current array overload, under its own name,
returning a plain `Promise<Component79[]>` — deliberately *not* chainable, since
mounting a list of components has no single meaning. `fetch` throws a
`TypeError` naming `fetchAll` when handed an array, so the old spelling fails
legibly instead of somewhere down in the parser.

The `$`/`$$` pair already establishes the singular/plural split in this library;
this is the same shape one level up.

## What it costs

- **`mount()` no longer returns the component.** On a handle it returns the
  handle, because the component does not exist yet. So
  `const app = C79.fetch(x).mount(el)` is a handle, and reaching the instance
  means awaiting it. This is a real asymmetry with
  `new Component79(src).mount(el)`, which returns the component, and the docs
  have to say so out loud. It is the price of the synchronous chain and the
  reason the handle exposes the whole lifecycle rather than just `mount`: a
  caller should never have to `await` merely to tear something down.
- **A dropped chain reports late.** `C79.fetch("/404.html").mount(el)` that
  nobody awaits surfaces its 404 as an unhandled rejection rather than a thrown
  error. That is the same behaviour a dropped `promise.then()` chain has today,
  and the handle keeps `catch`/`finally` for callers who want to handle it.
- **`fetchAll` is a breaking rename.** Pre-1.0, and the surface is three call
  sites in this repo (one docs snippet, two tests). The `TypeError` covers
  anyone outside it.

## Rejected

- **Making `fetch`'s array form chainable too**, with the first URL as the root
  and the rest registered as components available to it by filename. It is a
  genuinely useful feature and it is not this one: a file's own components
  already come from `<template name>`, and a setup script already reaches
  another file with `await import("./Row.html")`. Bolting a second, implicit
  registry onto a *loader* would make the meaning of `fetch` depend on the shape
  of its argument, which is exactly the ambiguity this proposal removes. If the
  registry is wanted, it wants its own entry point and its own plan.
- **A `Proxy` over the promise** that forwards unknown methods to the eventual
  component. Fewer lines, no maintenance as `Component79` grows — and no types,
  no way to tell "queued until it lands" from "already returned a value", and a
  `TypeError` for any method whose return value the caller actually needs.
  Explicit and boring wins.
- **Keeping the overload and dispatching on `Array.isArray`.** The whole point
  is that `fetch` should have one return type.

## Open

- Should `fetchAll` grow a settled variant (`Promise.allSettled`, one 404 leaves
  the rest usable)? Not now — the docs already say to fetch separately for that.
