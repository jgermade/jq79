# A trie node holds one effect, and allocates a Set for the second

**Status:** a plan, measured before `src/` moves. It follows the one consistent
performance signal left by
[`2026-08-27.grouping-a-row-s-bindings.md`](2026-08-27.grouping-a-row-s-bindings.md):
grouping made `clearLarge` 6-7% faster in every round of both runs while
`create1k` did not move at all - **teardown can see the effect count, creation
cannot** - so the teardown is where the per-effect cost is worth chasing.

---

## Where the teardown's time actually goes

Disposing 10,000 effects over a `$reactive` store, no DOM, median of 7:

| the shape of the effect's dependency | per effect |
| --- | --- |
| depth 1, all distinct (`k0`, `k1` …) | 0.39 µs |
| depth 2, all distinct (`rows.i`) | 0.38 µs |
| **depth 3, all distinct (`rows.i.label`) - a row binding** | **1.02 µs** |
| depth 3, ten rows shared by 1,000 effects each | 0.34 µs |
| no deps at all | 0.16 µs |

V8's own profiler around exactly the disposal window (node's, which attributes
JS frames properly): `removeDep` 26.7%, `unplaceAll` 22.6%, `forget` 13.7%,
**`isEmptyNode` 0.1%**.

Three spikes, each removing one candidate to price it:

| spike | disposal, per effect | |
| --- | --- | --- |
| baseline | 1.02 µs | |
| the empty-node pruning removed entirely | 0.90 µs | **not the cost** - 0.12 µs |
| the global `effects` Set removed (liveness as a flag) | 0.99 µs | **not the cost** - nothing |
| `node.own.delete(effect)` removed | **0.40 µs** | **that is the cost: 0.62 µs** |

So **60% of disposing an effect is deleting it from a `Set` that holds exactly
one effect.** Every trie node a row binding indexes has one effect on it -
`rows.7.label` is read by one text binding and nothing else - and a `Set` for
one entry is an allocation on the way in, a hash on the way out, and a second
object to reach through on a heap that has 30,000 of them.

## The proposal

The node's effect slot holds **the effect itself** when there is one, and
allocates a `Set` when a second arrives. It is the shape `indexEffect` already
uses one layer up, for exactly the same reason and in the same words:

```ts
// almost every effect ends up with exactly one dep once the redundant
// ancestors are pruned - a row binding reads one path - so the single case
// is held in two slots and the Map is allocated only when a second arrives
```

That comment is about `soleDep`/`soleNode`. This is its mirror: almost every
*dep* ends up with exactly one effect.

```ts
type EffectSlot = Effect | Set<Effect> | null
```

with four helpers (`addEffect`, `removeEffect`, `eachEffect`, `hasEffects`) and
`own`/`deep` typed as `EffectSlot` rather than `Set<Effect> | null` - so **tsc
finds every reader**, which is the whole safety argument: there are ten of them
and forgetting one would be a silently dead binding.

## What it should be worth

- **Teardown:** up to 0.62 µs per effect. A 10,000-row `clearLarge` disposes
  ~30,000, so ~18 ms of a ~104 ms operation - call it 15% if all of it lands.
- **Creation:** one fewer `Set` allocated per dep. Measured as a ceiling by the
  same method (an `insertDep` that touches nothing): 3.36 → 2.85 ms per 1,000
  one-dep effects, and 14.13 → 13.90 for the three-binding row. Small, and it
  is the same "the allocation was the cost, not the classification" lesson
  [`2026-08-23.where-the-create-time-goes.md`](2026-08-23.where-the-create-time-goes.md)
  has learned twice.
- **Nothing about wake semantics moves.** Same effects, same order, same deps.

## What it costs

- Ten call sites stop reading a `Set` and call a helper. Every one of them is
  `node.own?.forEach(effect => matched.add(effect))` today.
- One union type, and `instanceof Set` on the read path - which is a check V8
  folds away where the shape is stable, and where it is not, the alternative
  was a `Set` the whole time.
- A node whose single effect is removed must put its slot back to `null`, or
  `isEmptyNode` stops pruning and the trie grows. That is the one real hazard.

## What was measured and rejected on the way

- **Lazy or batched pruning of empty nodes.** `isEmptyNode` is 0.1% of the
  window and removing the prune loop entirely buys 0.12 µs. The trie's
  bookkeeping is not the problem.
- **Dropping the global `effects` Set** (liveness as a flag on the effect, the
  `isNewKey` sweep tracked in the `has` trap instead - the change
  [`2026-08-23.narrow-the-wake-rule.md`](2026-08-23.narrow-the-wake-rule.md)
  left open). Spiked: **no measurable difference at all**. It is still worth
  doing one day for the O(all effects) write it removes, but not for speed, and
  this file is not it.

## How each claim will be checked

| claim | sabotage that must turn it red |
| --- | --- |
| a single effect on a node still wakes | drop the single-slot branch from the walk |
| a second effect on the same dep still wakes | keep the slot single and overwrite |
| removing the only effect empties the node | leave the slot pointing at the removed effect |
| an emptied node is still pruned | assert the trie shrinks after a teardown |
| deep effects and own effects stay separate | write one into the other's slot |
