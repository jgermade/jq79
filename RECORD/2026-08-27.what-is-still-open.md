# What is still open

**Status:** a list, and the successor to
[`2026-08-25.open-after-the-box.md`](2026-08-25.open-after-the-box.md), whose
§1 (nobody has opened a browser) and §2 (the anchors) closed in PR #15, and
whose §6 diagnostics closed here except one - `:submit.prevent`, which is §2
below. That file is not edited; this one replaces it as
the map.

Not a proposal. Each item says what it is, what evidence exists, and how big it
looks. Ordered by what I would do first, which is not by size.

---

## 0. Three rules this session earned, before the list

**An operation under ~2 ms in the benchmark suite is at the instrument's
resolution.** Chromium reports it in 0.05 ms steps, so one step is 4-7% and a
"slower every round" verdict on `partialUpdate` (1.3 ms) means nothing. Three of
four runs called it a regression; timing 60 clicks as one batch inside the page
said −8.1%, faster in 6 of 6. `run-ab --only <id>` exists now so a small
operation can be given the samples it needs. See
[`2026-08-27.name-resolution-without-with.md`](2026-08-27.name-resolution-without-with.md).

**The benchmark can be the test.** Binding-grouping shipped behind a flag with
six sabotages red against it, and measured *exactly zero* - because the rule
said "contiguous ops" and the benchmark row's two text cells are separated by an
`@click`, so no group ever formed on the one template it was written for. No
test could see that; the measurement could.

**A sabotage that cannot go red is a finding, not a failure.** Three times over
now: `resolveName`'s in-scope and globalThis branches (masked by the demotion
net), a removed effect left in its trie slot (masked by the liveness check), and
member order inside a group (unobservable by construction). Each one either
earned a unit test at a lower level or got written down as observable-only-as-cost.

## 1. The release, which is the only thing with a clock on it

Three breaking changes are sitting unreleased on top of `0.6.4`, and the
*regression* workflow measures against the last released tag - so the longer
this waits, the less that gate is saying. The migration note is five lines:

- a component tag is an **element** in the DOM (`<c79-panel>`), so global CSS
  combinators stop crossing it and a parent's `:empty` stops matching;
- a component tag out of table-row position is foster-parented out, both
  spellings alike;
- `<mychip>` no longer upgrades, and a capitalized tag that resolves to nothing
  no longer falls back to the native element;
- **`:attrs` is gone** - bind one attribute at a time, `:class` for classes; the
  `class` and `value` *attributes* are now unwritable, since both names belong
  to their directives;
- `Component79.debug` grew `scopedNames` (and the A/B harness `--flags <name>`,
  `--only <id>`).

Nothing about it is a code question. It is the author's.

## 2. Small, ready, and nobody has argued with them

- **`:submit.prevent`.** The last unimplemented piece of
  [`2026-08-07.unknown-directive-warn.md`](2026-08-07.unknown-directive-warn.md):
  a dotted `:` name belonging to no family is a structural signal `plannableAttr`
  already computes, and it cannot fire on a legal binding. It is `@submit.prevent`
  written wrong, and today it writes an attribute called `submit.prevent`
  holding a stringified handler.
- **The dev server's second finding.** `jq79-devServer-issues.md` §2: a `watch`
  handler that copies a whole tree turns one edit into a burst of change events,
  and the first `.js` or `.css` in that burst downgrades a hot swap into a page
  reload. `fn(files)` exists precisely so a handler can copy only what changed,
  and `docs/dev-server.md` does not say so. One sentence and a second example.
  §1 (`.wasm` missing from `CONTENT_TYPES`) is fixed.

## 3. Where the performance work actually stands

Three changes were built and measured this session. What survived:

| | verdict |
| --- | --- |
| **Names resolved without `with`** | shipped. 865 ns → 316 ns for a one-name evaluation, 1515 → 429 for two. `selectRow` faster in all seven rounds across two runs (−15.5%, −22.0%); `create1k` −5.5% over 9 focused rounds |
| **Grouping a row's bindings by the names they read** | built, measured, **rejected**. `create1k` did not move; `partialUpdate` was 8-18% slower in every round of both runs |
| **One effect per trie node** | shipped, small. Isolated disposal 1.02 µs → 0.63 µs; `clearLarge` somewhere between −9% and −2%, and the best-instrumented run says −1.8% |

What that leaves, and it is the same answer from both ends of the object's life:
**the only structural lever left is fewer objects per binding.** Creation cannot
see the effect count and teardown can barely; what both see is how many separate
things exist per binding - an effect, its closures, a trie node, a Set. Grouping
was that lever and it cost more on update than it saved on create. Nobody has
proposed another one.

The `create1k` gap against Svelte is unchanged in kind: it is the price of an
interpreter with a cache in front of it, and closing it is a claim about what
jq79 is rather than an optimization anybody has left.

## 4. Open questions this session created

- **A name the extractor misses is read off `globalThis`.** `freeIdentifiers`
  not collecting a free name means the prologue does not declare it, so where
  the page has a global of that name (`name`, `status`, `length`, `top` - a
  browser window has hundreds) the expression silently reads the global instead
  of the store. Only a name that resolves *nowhere* throws, and only that throw
  reaches the demotion net. The differential corpus in
  `tests/expressions.test.ts` is the only thing standing under it; a fuzz over
  every expression in the tutorial and the benchmark app would stand better.
- **`resolveName`'s two branches are observable only as cost** - drop either and
  the expression demotes to `with` and gives the same answer, slower, forever.
- **`:attrs` left two holes on purpose**: no way to write an attribute set
  decided at runtime, and no way to write the `class` or `value` attribute at
  all. Nothing in this repository wanted either.
- **The `isNewKey` sweep is still O(all effects)**, and dropping the global
  `effects` Set with it was measured at **no speed win at all** - so if it is
  ever done, it will be for the write it removes, not for the teardown.

## 5. Unchanged from the previous list, and still the right trade

- **`<annotation-xml>` stays off the clone path**, taking its `<math>` ancestor
  with it. Slower and correct.
- **`renders=8` never resolved**; the break-even curve needs a smaller chunk.
- **The order axis is differential only** - it compares the two render paths
  against each other, so a change that reorders both identically still passes.
- **`moveRangeAfter` still moves a reorder one node at a time.** A *component*
  row is one node now, so its reorder is one `insertBefore`; the benchmark app's
  rows are plain `<tr>`s, so the number does not move.
- **A component cannot style its own box**, and whether it should be able to (a
  `:host`-shaped selector) is a question nobody has asked.
- **`ensureWrapperStyle()` is never released** - one rule, no refcount,
  deliberately.

## 6. Housekeeping

- **`tests/vitePlugin.test.ts` writes to a fixed bundle path**; two concurrent
  vitest processes would overwrite it mid-import. Latent, not a flake: CI is
  single-process.
- **The stress harness is still not in the repo.** A shell loop per core plus
  repeated `npx vitest run`, then read *which* assertion failed.
- **jsdom and Chromium disagree about a component inside `<select>`** - jsdom
  drops an unknown child, Chromium keeps it. This repo's tests are not
  authoritative about that position.
- **The benchmark app has no component tag in it**, so nothing in the published
  table can price anything about nested components - including the ~2.5 µs per
  instance the retired anchors were costing.
- **`frameworks/keyed/jq79/node_modules` is removed and rebuilt by every A/B
  run**, so a `vite preview` of that app between runs needs `configFile: false`.

## 7. The part none of this touches

Unchanged and still honest: `create1k` is ~25-30 ms on this runner where Svelte
is a fraction of that, and after this session the remaining time is one effect
per binding *minus* the `with` that used to sit inside every evaluation of it.
The two things ever priced against the rest - grouping a row's bindings, and
dropping `with` - are now one rejected and one shipped.
