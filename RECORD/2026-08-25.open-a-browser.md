# Open a browser

**Status:** plan, written before a line of it existed. It takes §1 of
[`2026-08-25.open-after-the-box.md`](2026-08-25.open-after-the-box.md) - *nobody
has opened a browser* - which that list calls the largest gap and the cheapest to
close.

---

## The problem

Step 2 of the tag rename put an element where every component instance used to be
four comment nodes, and gave it one line of CSS:

```css
:where([data-c79-box]) { display: contents }
```

Everything asserted about that line is jsdom's. jsdom has no layout and no
cascade: it can say the rule is *in* `document.head`, and it cannot say that a
component's children still lay out as flex items, or that an author's
`c79-panel { display: flex }` outranks it. Four claims are specification
reasoning with a jsdom-shaped test under them:

1. **`display: contents` leaves flex and grid layout unchanged.** The wrapper
   proposal says it was measured; it was not re-measured after the rule became
   `:where([data-c79-box])`.
2. **`:where()` really does let an author rule win**, without `!important` and
   whatever order the browser saw the stylesheets in.
3. **A component in table-row position is foster-parented out** - measured
   through jq79's parse, which is jsdom's parse.
4. **A wrapper inside `<svg>` would take its children with it**, which is the
   whole reason decision 4 skips the box in a foreign namespace. If it is wrong,
   the exception is unnecessary.

## The proposal

One script, `scripts/check-box-layout.mjs`, in the shape
`scripts/check-svg-attribute-names.mjs` already established: a page per claim, a
table printed even when everything passes, `--json` per engine, `--compare` for
the job that can see all three, and two levels of which only one gates.

It measures **the built bundle** (`dist/jq79.global.js`) in a real page, not the
source through a test runner. The claims are about what a browser does with what
the library ships, and the bundle is what it ships.

### Every probe carries its own counterfactual

The rule this branch earned is *write the sabotage before trusting the check*,
and its second half: a green check nobody has seen fail is not evidence. Both
halves are cheaper here than they have ever been, because the sabotage is a
stylesheet - so each gating probe measures **twice**, once as shipped and once
with the mechanism defeated, and asserts the two answers differ:

| probe | as shipped | defeated by |
| --- | --- | --- |
| flex | children lay out exactly as the control | `c79-item { display: block }` |
| grid | same, in a three-column grid | the same rule |
| `:where()` | the author's `display: flex` wins | the rule written without `:where()` |

A probe whose counterfactual measures the same as the real thing has proved
nothing, and says so with a failure rather than a pass. That is the vacuity
[`2026-08-24.clone-path-coverage-check.md`](2026-08-24.clone-path-coverage-check.md)
exists to catch, moved one level up: there it was "did the second path run", here
it is "could this measurement have come out any other way".

### The control is measured in the same page, not written down

Layout numbers depend on the viewport, the default font and the engine, so
nothing asserts that `.b` is at x=108. Each layout probe renders the same markup
**twice** - once with the middle child rendered by a component, once written
inline with no component at all - and asserts the two agree rect for rect. That
comparison is engine-independent by construction, which is what lets the same
gate run in three engines.

### Two levels, and only one gates

- **Level 1, ours, and it fails a build.** The box does not disturb flex or grid
  layout; an author rule outranks the default. Both come with the counterfactual
  above, and a counterfactual that does not move fails too.
- **Level 2, the platform's, and it reports.** Where a component tag lands in
  table-row position, what an `<svg>` does with an unknown element around a
  component, whether a parent's `:empty` still matches. These are facts about the
  web platform and about costs already written down; an engine that answers
  differently is news, not a defect, and the table is the only place this repo
  will hold it.

## What it costs

A workflow and a script. Playwright is already a devDependency and the browsers
are already cached by the oracle's workflow; `src/` is not touched, so nothing
ships to a page that did not before. The run is one page per claim - three
engines finish in about the time the oracle takes.

## What was rejected

- **Putting it in vitest.** The gap *is* jsdom. A test that runs where there is
  no layout cannot close a claim about layout, whatever it asserts.
- **Screenshots and pixel diffs.** Brittle across engines and fonts, and they say
  "something moved" where a rect says which box moved and by how much.
- **Asserting absolute geometry.** It bakes in a viewport and a font, and it
  makes the check engine-specific for no gain - see the control above.
- **One page for every probe.** The wrapper rule is injected into
  `document.head` on the first box and deliberately never removed (§5 of the open
  list), so a later probe would inherit an earlier probe's stylesheet and could
  pass for the wrong reason. This was not hypothetical: it happened while
  exploring, and the reading it produced was a wrapper whose computed display was
  `inline` because the probe before it had not yet made one. A page per probe.
- **Driving the tutorial or the site.** Heavier, and it measures a build step
  rather than a claim.

## What is still open after it

- It does not test **Safari**, only Playwright's WebKit - the same caveat, for
  the same reason, as the oracle's workflow.
- It measures the four claims and the costs, not the whole of step 2. Nothing
  here looks at hot reload, `:each` moves or the swap path in a browser.
- If claim 4 comes back false - a wrapper inside `<svg>` renders its children
  after all - the exception in `componentBox` is unnecessary, and removing it is
  a separate change with its own evidence. This says which, it does not do it.

## Update, 2026-08-25: run, and three things the plan above got wrong

The results are [`2026-08-25.what-the-browser-said.md`](2026-08-25.what-the-browser-said.md).
What differs from the plan as written:

- **The `<svg>` probe is level 1, not level 2.** The plan filed it with the
  platform's answers. Deleting the exception it protects turns a drawing into a
  blank in a real browser, which makes "a component inside `<svg>` still paints"
  a claim about our code - so it gates, against a control drawn without a
  component. What stays a report is the opposite direction: an engine that
  renders a wrapped child anyway makes the exception unnecessary, not wrong.
- **The grid probe's first shape could not fail**, and its own counterfactual
  said so on the first run - three equal tracks put the child in cell 2 whether
  the box is `contents` or `block`. Uneven tracks and a span.
- **The layout sabotage had to become `!important`.** At 0-0-1 it lost to a
  default rule written without `:where()`, so one broken cascade reported itself
  as three blind probes.

The measurement also found something the four claims did not cover: a component
whose template root is a bare SVG element is an HTML element and never draws.
That is documented and pinned now, and *why* it is that way is a design question
nobody has asked.
