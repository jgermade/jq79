Why jq79

The file you write is the file you ship

Most component frameworks need a toolchain between your source and the browser. jq79 moves that step into a {{gzip}} runtime, so the browser can take your components as they are.

⚡

No build step

Import the library from a CDN, fetch a component from your own host, mount it. That is the whole deployment.

📄

A component is one file

Markup, a setup script and styles side by side, in a .html file any editor, server or CDN already understands.

Hello {{ name }}!
🧮

Variables are state

Top-level let and const are reactive, and $: derives from them. No hooks, no signals to unwrap, no setState.

🎯

Fine-grained updates

Proxies track what each binding read. A write re-runs only those bindings — no diffing, no re-rendering the component.

rows[3].label = "renamed" // one text node changes; the other // 999 rows aren't even looked at
📦

Code splitting is the file system

An import() of an .html fetches that component when the line runs. The chunk is the file; there's no chunk graph to configure.

const Chart = await import("./Chart.html")
🧰

Tooling when you want it

A dev server with hot reload, a Vite plugin, TypeScript in setup scripts, a VS Code extension, and a CSP-safe mode. All optional.

npx jq79 dev # serve + hot reload

With npm, for a bundler or the dev tools:

npm install jq79
Components docs

02Put it on a page

C79.fetch() downloads a component and hands back a pending one you can mount straight away — every call queues on the download. The second argument is the component's props.

Awaiting it gives you the component itself; fetchAll() loads several in parallel. Each URL is downloaded once and reused by later fetches and imports — Component79.cache(false) turns that off.

const app = await C79.fetch("./app.html").mount("#app") const [Header, Footer] = await C79.fetchAll(["./Header.html", "./Footer.html"])

    06Stores & services

    When two components need the same state, make it a store. $reactive works anywhere — including a plain module, which is all an app-wide service needs to be. $computed derives from it.

    import { $reactive, $computed } from "https://esm.sh/jq79" export const cart = $reactive({ items: [] }) export const total = $computed(() => cart.items.reduce((sum, item) => sum + item.price, 0) ) export const add = item => { cart.items = [...cart.items, item] } {{ cart.items.length }} items · {{ total.value }} €

    Every component that holds the store sees every write, whoever made it. A store passed as a prop is shared the same way — no context API, no injection.

    08Develop

    No bundler: npx jq79 dev serves your folder as-is and hot-reloads the components you edit, keeping their state.

    npx jq79 dev # http://localhost:4179

    With Vite: the plugin imports .html components as modules, with HMR and TypeScript in setup scripts. The same files keep working when fetched at runtime.

    import { jq79 } from "jq79/vite" export default { plugins: [jq79()] } import App from "./App.html" App.mount("#app")

    In your editor: the VS Code extension highlights and type-checks components; jq79-check does the same in CI.

    Dev serverVite pluginVS Code extension

    09Ship

    Upload the folder to any static host — GitHub Pages, S3, a CDN. There's no build output because there's no build. For a page with a strict Content Security Policy, safeEval runs without 'unsafe-eval', with or without a bundler.

    import { C79 } from "https://esm.sh/jq79@%VERSION%" // pin it await C79.safeEval() // no new Function, ever C79.fetch("./app.html").mount("#app")
