# `deep` is the way back from the narrowed wake rule, so it has to be sayable

**Status:** proposal. Follows
[`2026-08-23.narrow-the-wake-rule.md`](2026-08-23.narrow-the-wake-rule.md),
which removed a behaviour and added the mechanism that restores it without
documenting the second half. Nothing implemented at the time of writing.

## The gap

Narrowing the wake rule took one thing away, and exactly one:

```js
const store = $reactive({ payload: { n: 1 } })
store.$effect(() => send(store.payload))   // hands the object to opaque code
store.payload.n = 2                        // before: re-runs. now: silent.
```

Measured against `main`, this is the whole of the behaviour change. Every
ordinary shape is unaffected — `{{ user.name }}` and every binding that reads
a field, `$on("user")` (exact-match, and it never fired for deep writes
anyway), `Object.keys`/spread/`for…in` (now tracked through the `ownKeys`
trap), nested `$reactive` stores (bridge boundary), props forwarded to a child
(the prop sync's own `deep` flag). Even `{{ user }}` in a template is
unobservable either way: with a default `toString` it re-renders
`[object Object]` identically, and with one that reads fields it tracks them
and wakes.

What is left is the case the model genuinely cannot see into: an effect that
hands a value to code outside the store's view — a chart library, a canvas
draw, an API call. No amount of finer tracking fixes that, because the reads
happen where the proxy is not.

`$effect`'s third parameter already restores it —
`store.$effect(run, undefined, true)` wakes for anything under the effect's
deps — and it is in the public `ReactiveDeepData` type. It is also
**undocumented**, which is the worst of the three possible states: a documented
removal with an undocumented escape hatch.

## Why not just document it as it stands

Because the signature is `$effect(run, alsoWakenBy, deep)`, and `alsoWakenBy`
is internal — it carries the extra stores slot content must also wake from
(see `ATTACH`). Documenting `deep` as the third positional means either
documenting `alsoWakenBy` too, or telling people to write `undefined` in the
middle. Both freeze a shape that exists for the library's convenience.

A grep settles how free the change is: **exactly one call site in the whole
repo passes more than one argument** — `createEffectScope`
(`src/reactive.ts:837`). No test, no doc, no `dev/` code. Both extra
parameters are internal plumbing that reached the public type by accident of
implementation.

## The proposal

`$effect(run, options?)`, with `options` an object:

- the public `ReactiveDeepData` type declares `{ deep?: boolean }` and nothing
  else;
- the implementation also accepts `alsoWakenBy` on the same object, commented
  as internal — the same arrangement `ATTACH` already has, where a name exists
  for the library and is kept out of what users are told about;
- `createEffectScope` is the one call site to update.

Then document `deep` in `docs/reactive-data.md`, beside the section that
already explains the narrowed rule, so the removal and the way back are read
together. And fix that file's line 14, which still calls the effect
"fine-grained, deep" — precisely the adjective this change qualified.

## What it costs

- `deep` becomes supported API. Any future rework of the core — the
  per-property signals rewrite rejected in `2026-08-23.narrow-the-wake-rule.md`
  among them — has to keep honouring it.
- One more concept in a small API. The mitigation is that it is documented as
  what it is: the answer for handing a value to code the store cannot watch,
  not a general-purpose knob.

## Rejected

- **Leaving it undocumented.** The removal is documented and pinned; leaving
  the recourse out means a user whose effect silently stops running has no way
  to find the fix short of reading `reactive.ts`.
- **Pointing at `$onAny` instead**, with a prefix filter:
  ```js
  data.$onAny(dotKey => { if (dotKey.startsWith("payload")) send(data.payload) })
  ```
  Works today, is already documented, keeps the surface minimal — and makes
  the user handle dot-paths by hand, which is the plumbing the store exists to
  hide. It also loses the effect's own teardown and its first run.
- **Keeping the positional third parameter and documenting both.**
  `alsoWakenBy` is not something a user of this library should ever need to
  know about; publishing it to explain `deep` gets the trade backwards.
