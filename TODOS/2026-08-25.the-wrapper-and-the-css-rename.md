# The wrapper in the DOM, and the same rename in the CSS

**Status:** plan, written before `src/` was touched. This is **step 2** of
[`2026-08-25.component-tag-prefix.md`](2026-08-25.component-tag-prefix.md),
whose step 1 landed in [PR #14](https://github.com/jgermade/jq79/pull/14). That
file stays the proposal and the record of step 1; this one is where step 2's own
decisions are argued, because four of them are not in it and one of them
contradicts what it left open.

---

## What step 1 left standing

A component that resolves still renders as **four or five comment nodes and no
element**, exactly as before the rename:

```
one root     <div class="w"><!--One--><!--jq79--><p class="a">uno</p><!--/jq79--><!--/One--></div>
no root      <div class="w"><!--None--><!--jq79--><!--if--><!--/jq79--><!--/None--></div>
```

The `c79-*` tag exists in the source and in the DOM of a component that has
*not* resolved. Step 2 is the half that makes it real:

```
one root     <div class="w"><c79-one data-jq79-component><!--One-->…<!--/One--></c79-one></div>
no root      <div class="w"><c79-none data-jq79-component><!--None-->…<!--/None--></c79-none></div>
```

and lets a `<style scoped>` name the component the author wrote:

```css
Circle { color: red }   ->   c79-circle[data-jq79="155h7tu"] { color: red }
```

## Decision 1: the wrapper carries the PARENT's stamp

The previous file left this open and called "the child's stamp" the answer that
preserves today's behaviour. **It is the wrong one, and the mechanism says so.**

A `<style scoped>` is rewritten to demand *the stamp of the component that wrote
it*. The author writing `Circle { color: red }` is the **parent**, so the rule
becomes `c79-circle[data-jq79="<parent's hash>"]`. Give the wrapper the child's
stamp and that rule matches nothing - which makes the CSS rename, the headline
of step 2, inert.

It also falls out for free, and that is the tell: `stampScope` walks the
parent's AST and stamps every node of it, and the component tag **is** a node of
the parent's template. The stamp is already sitting in `node.attrs`; today it is
dropped because there is no element to put it on.

So the wrapper is an element of the parent's template, like every other element
the parent wrote, and it is stamped like one. What does *not* change: the child's
own root carries no stamp from the parent, so a parent's scoped rules still
cannot reach *inside* the child. The parent gets the box, not the contents.

**The cost, said out loud:** a component's own `<style scoped>` cannot style its
own wrapper - the wrapper is not part of its template, so it never carries the
child's hash. `c79-panel { display: flex }` written *inside* Panel does nothing;
written by Panel's parent, or in a global stylesheet, it works.

## Decision 2: the wrapper is named after the component, not the usage site

`<UserCard />` and `<user-card>` resolve to the same component and now render the
same box: `<c79-user-card>`. The name comes from the **resolved scope key**, not
from `node.tag`, so the CSS rewrite has one name to target however the tag was
spelled. A dashed usage site keeps its own tag nowhere - which is a small loss of
fidelity in the inspector, and the price of `UserCard { … }` meaning one thing.

## Decision 3: `display: contents` rides on a marker attribute, not the tag

The previous file wrote the default as `c79-* { display: contents }`. **That is
not a selector** - CSS has no prefix matching on type selectors, and a wrapper
is not always `c79-*`-shaped anyway if decision 2 ever changes. Three candidates
were considered:

- **One rule per component name**, refcounted through the existing style
  registry. Works, self-cleans, and costs a map lookup per instance - but a
  wrapper inside a shadow root needs the rule *in that root*, and the parent's
  style elements are the only thing that reaches it. That means the parent
  carrying a rule for each of its children's names. Rejected as the most moving
  parts for the least.
- **An inline `style="display:contents"` per wrapper.** No stylesheet anywhere,
  and an author override then needs `!important`. Rejected.
- **A marker attribute and one rule** - what this takes. Every wrapper gets
  `data-jq79-component`, and one stylesheet carries

  ```css
  :where([data-jq79-component]) { display: contents }
  ```

  One rule covers every wrapper in the document, and one copy prepended to a
  shadow-rendered instance's style elements covers every wrapper in that root.

**`:where()` is load-bearing.** It has zero specificity, so *any* author rule
wins - `c79-panel { display: flex }` (0-0-1) beats it without `!important` and
without depending on which stylesheet the browser saw first. Without `:where()`
the default would either outrank the author (source order) or lose to nothing at
all.

## Decision 4: no wrapper inside `<svg>` or `<math>`

The previous file's "always" was argued in HTML terms - a tree whose shape does
not depend on runtime content. In a foreign namespace the trade is different:
SVG's rendering model does not render an unknown element **or its children**, and
`display: contents` is not the escape hatch there that it is in HTML. A wrapper
around a component that renders `<circle>`s could therefore render nothing at
all.

So a component tag whose `ns` is set keeps today's anchors and gets no wrapper.
It is an exception, it is namable in one line - *the wrapper is an HTML
mechanism* - and the alternative is a silent blank where a diagram was.

Not measured here: jsdom has no layout, so this is the conservative reading of
the rendering model rather than a measurement. Anyone with a browser can settle
it, and the exception is the safe side to be wrong on.

## The CSS rename runs BEFORE the parser, not on `selectorText`

The obvious implementation rewrites `rule.selectorText` beside the scope
attribute, in `scopeRules`. **It cannot go there.** In an HTML document a type
selector is matched case-insensitively, and engines are free to lowercase it when
they serialize: jsdom hands `Circle` back as `Circle`, and a Blink-shaped engine
that hands back `circle` would leave the rewrite matching nothing - a feature
that works in this repo's tests and does nothing in a browser. That is exactly
the failure mode PR #13 earned its rule about.

So the rename is a **source transform**, before any parser sees the CSS:
`renameComponentSelectors(css)` scans the text, tracks strings, comments and
block nesting, and rewrites capitalized identifiers **only in selector
position** - never inside a declaration block, never inside an at-rule prelude
(`@import url(Foo.css)` is left alone), never after `.`, `#` or inside a string.
It runs on every style block that is real CSS, so scoped, unscoped and
shadow-rendered styles all get it, and a `lang` block (uncompiled SASS) is left
as written, exactly as scoping already leaves it.

**Which names it rewrites:** a capitalized identifier *containing a lowercase
letter* - `Circle`, `UserCard`, `Tr`. Not `DIV`, `A`, `SPAN`: shouty type
selectors are established CSS practice and case-insensitive matching is what
makes them work, where in markup the same spelling is now a component claim
(step 1). The two rules differ, deliberately: in markup `<DIV>` was made loud
because the alternative was silence; in CSS `DIV { }` still means `div`, and the
corner it leaves is a component named with no lowercase letter at all (`ABC`),
which cannot be styled by name. Documented, not silent-by-design.

## What this does not do

- **The anchors stay.** A component still renders `<!--Name-->…<!--/Name-->`
  inside its wrapper. The wrapper *is* the stable handle the anchors exist to be
  (`boundsOf` already resolves an element as `{ first: el, last: el }`), so the
  component pair is now redundant - but retiring it is §4 of the open list, on
  its own evidence, not part of this.
- **No version bump.** Step 1's migration note grows a fourth line here (a
  component is an element in the DOM now) and nobody has cut the release.

## What it costs, and what pays for it

- `.grid > .item`, `+`, `~` and `:nth-child` crossing a component boundary stop
  matching in **global** CSS. Inside jq79's own scoping there is nothing to lose:
  a parent's scoped rule already could not reach a child's root.
- A parent's `:empty` stops matching when the child renders nothing.
- One `setAttribute` and one element per instance.
- Against that: a reorder of component rows moves **one node** instead of
  walking a range (`moveRangeAfter` is one `insertBefore` when first === last),
  and a component finally names itself in the inspector.

## How each claim will be checked

Sabotage first, per the rule PR #13 earned. Written down here so the list is
fixed before the code exists:

| claim | sabotage that must turn it red |
| --- | --- |
| every instance gets a wrapper, including the empty one | return the fragment for the no-root case |
| the wrapper carries the parent's stamp | stamp it with the child's |
| `Circle { }` reaches the box | drop the rename from the style pipeline |
| the rename never touches declarations | rewrite the whole sheet, not selector positions |
| the default is overridable | drop the `:where()` |
| a component inside `<svg>` gets no wrapper | wrap it anyway |

## Update, 2026-08-25: implemented, and four adjustments the plan above got wrong

The plan is left as written; what follows is what the code does where it differs,
and why. Every check in the table above was broken on purpose first and went red;
so did two the plan did not list.

- **The marker attribute is `data-c79-box`, not `data-jq79-component`.** The
  first name reads like a scope stamp - `data-jq79` is exactly what the scoped
  rewrite writes - and a shadow-root test asserting "no `data-jq79` in this CSS"
  would have been failed by a rule that has nothing to do with scoping. The tag
  and the marker now read as a pair: `<c79-user-card data-c79-box>`.
- **The wrapper rule goes LAST among a shadow-rendered instance's styles**, not
  first. Position decides nothing (`:where()` has no specificity), and appending
  keeps "the shadow root's `<style>`" meaning the component's own, which is what
  the existing tests read.
- **A shadow-rendered box injects nothing into `document.head`.** The plan said
  the rule ships to both places; it must not ship to head from a shadow tree,
  because "a shadow-rendered tree leaves `document.head` alone" is an invariant
  with a test on it. `componentBox` takes `shadow` and skips the head injection.
- **Strings and comments end the renamable chunk.** The first scan appended them
  to the prelude and renamed the whole thing, so `[title="a > Boo"]` would have
  had its `Boo` rewritten inside the string. They are emitted verbatim now, and
  the at-rule test reads the whole prelude rather than the surviving chunk - or
  `@supports (font-family: "X")` would stop looking like an at-rule the moment
  its string was split off.

Two sabotages beyond the plan's table, both red before the fix: renaming the
whole sheet instead of selector positions, and treating a string as renamable
text.

**Measured nowhere:** the box is one element and one `setAttribute` per
component instance, and the benchmark app renders no nested components, so
nothing in this repo's numbers moves either way. The CI benchmark on the PR is
the only measurement, and a delta under the runner's noise is not a result.

**The benchmark ran, and could not have said anything.** `1c01e44` on an EPYC
9V74: `regressions: []`, every operation inside the noise. That is not evidence
the box is free - the benchmark app renders **no nested components**, so step 2
touches none of the code that runs per row, and its cost (one element and one
`setAttribute` per instance) is invisible to every operation in the table by
construction. Anyone wanting that number has to write the app that pays it.
