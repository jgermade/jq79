# `$updateModel` — the writeback stops being an event

**Status:** decided (user's proposal and user's call on the fork). Replaces the
child-side half of `2026-07-15.model-directive.md`; the `:model` attribute, the
prop-down, the name normalization and the warns all stay as that plan pinned
them.

## The problem

The writeback a `:model` child performs is, today, a hand-assembled event:

```js
$emit('model:update', { name: 'isDragOver', value })
```

Three things are wrong with it, and all three are the same thing — the emit
site is spelling out a protocol instead of calling an API:

- **The payload is a shape the author has to get right**, at every emit site,
  with no help until runtime. `{ name, valeu }` warns; `{ name, value }` inside
  a stray extra object doesn't. The original plan's answer was the strict
  `{ name?, value }` contract plus a `console.warn` for everything else — a
  validator existing because the API let the mistake be expressible.
- **The name is a magic string in userland.** `model:update` is jq79's, not the
  component's, but it sits in the child's template looking exactly like the
  component's own `$emit('saved', …)`.
- **The transport is a DOM CustomEvent** that bubbles out through the page on
  every keystroke, `composed: true`, past every ancestor, to be heard by
  nobody but the parent's `on()` listener — which is not a DOM listener.

## The proposal

One instance helper, next to `$emit` and `$slots`:

```js
$updateModel(value)                  // 1 arg  -> the default model (bare :model)
$updateModel('isDragOver', value)    // 2 args -> the named model
```

Returns whether a bound model took the update.

**Arity is what disambiguates**, and this is the piece that makes the helper
possible at all. `2026-07-15.model-directive.md` rejected
`$emit("model:update", value)` as a default-model shorthand because it is
"ambiguous the moment the value *is* an object with `name`/`value` keys" — that
rejection was about *inspecting a payload's shape*. A function never inspects:
one argument is a value of any shape whatsoever, two arguments are a name and a
value. The only casualty is "name with an absent value", which is
`$updateModel('uname', undefined)` — still two arguments, still exact.

**And the transport goes with it.** The usage site hands the child instance its
writeback directly (`instance.modelWriteback = …`, set where
`instance.slots` already is, before the first render); `$updateModel` calls it.
`model:update` stops being an event name jq79 knows about:

- no CustomEvent per keystroke, no `composed: true` trip through the page for a
  parent-child assignment;
- the payload-shape warn is deleted rather than kept — the shape it validated
  can no longer be constructed;
- `@model:update` on a wrapping element hears nothing, because there is nothing
  to hear. That was never a documented listening point, but it worked, and
  after this it doesn't.

## Semantics pinned

- **Normalization stays on the parent side**, where the names are: `undefined`
  name means `"default"`, anything else goes through `kebabToCamel`. So
  `$updateModel('user-name', v)` and `$updateModel('userName', v)` both find
  `:model.user-name`, exactly as the payload's `name` did.
- **The stale-generation guard is kept.** `$updateModel` captures its marker
  and compares it to `this.startMarker` before calling the writeback, like
  `$emit` does — `destroy()` nulls the marker, so a closure the old child
  leaked (a timer, a registered callback) cannot keep writing the parent. This
  is the ghost-writeback containment the 2026-07-15 audit addendum pinned, and
  it has to be re-established by hand because it is no longer inherited from
  `$emit`.
- **`untracked` stays**, now inside the writeback the parent builds, for the
  reason the audit addendum gives: an imperative writeback is nobody's
  dependency, independent of the two containments that happen to make it
  harmless today.
- **Return value**: `true` when a bound model was assigned; `false` when no
  `:model` binds that name, when the expression was already found
  unassignable at wiring time, or when there is no `:model` on the tag at all.
  Assignability is recorded at wiring time (the `compileExpr` check already
  runs there) rather than inferred from the assignment's result — a successful
  assignment of `undefined` and a dropped one are otherwise identical.
- **No `:model` on the tag is a silent no-op**, not a warn: a child may be
  designed to work bound *or* unbound, and warning would fire on the legitimate
  case. A typo'd name still warns loudly (once per name per instance), because
  that path only exists when the site did bind something.
- **A store key named `$updateModel` shadows the helper**, like `$emit` and
  `$slots` — it goes in the same `injected` map, so template reach, both script
  modes and the shadowing rule are all inherited, not re-implemented.

## The breaking change, and the one concession

Children written against the old contract break — `$emit('model:update', …)`
now dispatches an event nobody listens to, and their edits vanish. That is the
failure mode this plan family has repeatedly refused to ship, so `$emit` warns
once per instance when it is handed `model:update`, naming `$updateModel`. It
does not route the call: the point of the fork was to remove the second path,
not to keep it behind a warning. A component legitimately emitting its own
event by that name gets a spurious warn; it is a warn, and the name was jq79's
first.

## What it costs

- `$updateModel` in the instance helpers (~10 lines), a `modelWriteback` field
  on `Component79` (~3), the usage site's listener becoming that function
  (~5 changed), the deprecation warn in `$emit` (~4).
- Deleted: the payload-shape validation and its test.
- Docs (`template-syntax.md`, `setup-scripts.md`), the two-way-binding tutorial
  lesson and its solution, and ~25 emit sites across the test suite.

## Rejected

- **Sugar over the event** (`$updateModel` compiling to the same `$emit`) —
  non-breaking, and keeps `@model:update` on a wrapper working; rejected by the
  user in favour of removing the second path outright. It would have kept the
  payload validator alive forever to serve emit sites the API no longer
  produces.
- **Sugar now, deprecate later** (the same, plus a warn on hand-written emits)
  — same objection, plus a migration window nobody in a pre-1.0 library asked
  for.
- **Warning when `$updateModel` is called with no `:model` bound** — see above;
  bound-or-unbound is a legitimate design for a child.
- **Returning the assignment's value instead of a boolean** — indistinguishable
  from a dropped update when the value is `undefined`.
- **Keeping the shape-validating warn as well** — nothing can reach it.

## Open

- `:model` on native elements is still parked, as `2026-07-15.model-directive.md`
  left it. Nothing here touches that decision.
